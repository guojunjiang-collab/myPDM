## 1. 功能概述

### 1.1 模块划分

构型配置模块包含两个 Tab：

| Tab | 功能 | 状态 |
|-----|------|------|
| **构型项管理** | 定义构型项、关联零部件、子构型项层级、关联图文档 | ✅ 已上线 |
| **构型配置** | 基于构型项生成配置方案，设定架次有效性 | ✅ 已上线 |

### 1.2 什么是构型配置

构型配置解决的是"**某架次飞机具体用哪些零件**"的问题。

- **构型项**定义了一个产品单元的**所有可能**组成（必选件 + 可选件）
- **构型配置**是为特定架次范围**确定**最终选用清单

### 1.3 核心能力

- **选择构型项**：从构型库中选取需要配置的构型项（新建时可暂不关联，编辑时再关联）
- **自动展开清单**：根据构型项的必选/可选标记，递归生成层级配置清单
- **层级勾选**：支持构型项节点级整体勾选/取消，一键切换子节点下所有零部件
- **架次有效性**：指定该配置适用于哪些架次号（起始/结束范围）
- **状态管控**：草稿 → 生效 → 归档，管理员可通过单选框直接切换
- **正式配置清单**：自动汇总已勾选的构型项和零部件，形成最终输出

## 2. 数据模型

### 2.1 新增表

#### `configuration_profiles` — 构型配置主表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | UUID | PK | 主键 |
| `code` | VARCHAR(64) | UNIQUE NOT NULL | 配置编号 |
| `name` | VARCHAR(255) | NOT NULL | 配置名称 |
| `configuration_item_id` | UUID | FK→configuration_items, **NULLABLE** | 关联构型项（新建时可不填） |
| `status` | VARCHAR(16) | NOT NULL, DEFAULT 'draft' | draft / active / archived |
| `effectivity_start` | VARCHAR(32) | | 起始架次号 |
| `effectivity_end` | VARCHAR(32) | | 结束架次号 |
| `remark` | TEXT | | 备注 |
| `creator_id` | UUID | FK→users, NOT NULL | 创建人 |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | |
| `updated_at` | TIMESTAMPTZ | DEFAULT NOW() | |

#### `configuration_profile_items` — 配置清单明细表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | UUID | PK | |
| `profile_id` | UUID | FK→configuration_profiles, CASCADE | 所属配置 |
| `source_config_item_id` | UUID | FK→configuration_items | 来源构型项 |
| `item_type` | VARCHAR(16) | NOT NULL | 'part' / 'assembly' |
| `item_id` | UUID | NOT NULL | 零部件 ID |
| `item_code` | VARCHAR(64) | | 零部件编号（冗余） |
| `item_name` | VARCHAR(255) | | 零部件名称（冗余） |
| `is_required` | BOOLEAN | NOT NULL, DEFAULT TRUE | 是否必选（继承自构型项定义） |
| `is_selected` | BOOLEAN | NOT NULL, DEFAULT FALSE | 最终是否选用 |
| `source_type` | VARCHAR(16) | NOT NULL | 'direct' / 'child' |
| `sort_order` | INTEGER | DEFAULT 0 | |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | |

### 2.2 配置清单生成规则

创建/编辑配置时选择构型项 → 递归展开：

1. 查询 `configuration_item_parts` → 插入清单项，`source_type='direct'`
2. 递归 `configuration_item_children` → 插入清单项，`source_type='child'`
3. 必选件 `is_required=true` → `is_selected=true`
4. 可选件 `is_required=false` → `is_selected=false`

> 重新关联同一构型项会清除旧清单并重新生成，确保数据一致性。

## 3. 状态流转

### 3.1 状态图

```
        ┌─────────┐              ┌──────────┐              ┌───────────┐
        │  draft  │ ── 生效 ──→  │  active  │ ── 归档 ──→  │ archived  │
        │  草稿   │              │  生效中   │              │  已归档   │
        └─────────┘              └──────────┘              └───────────┘
             ↑                        │                         │
       管理员可通过单选框               │                         │
       直接切换任意状态 ←──────────────┴─────────────────────────┘
```

### 3.2 各状态含义

| 状态 | 阶段 | 说明 |
|------|------|------|
| **draft** | 编制 | 工程师正定方案，可任意修改配置清单和基本信息 |
| **active** | 执行 | 生产线以此为准，不可修改配置清单 |
| **archived** | 归档 | 飞机已交付，仅作历史追溯 |

### 3.3 各状态操作权限

| 操作 | draft | active | archived |
|------|:-----:|:------:|:--------:|
| 编辑基本信息 | ✅ | ❌ | ❌ |
| 修改配置清单 | ✅ | ❌ | ❌ |
| 删除配置 | ✅(管理员) | ✅(管理员) | ✅(管理员) |
| 查看 | ✅ | ✅ | ✅ |

## 4. 架次有效性

使用 `effectivity_start` + `effectivity_end` 表示架次范围。

| 场景 | effectivity_start | effectivity_end |
|------|-------------------|-----------------|
| 单架次 | MSN042 | MSN042 |
| 连续批次 | MSN001 | MSN050 |
| 不限范围 | 留空 | 留空 |

## 5. API 设计

### 5.1 端点总览

| 方法 | 端点 | 说明 | 权限 |
|------|------|------|------|
| `GET` | `/configurations/profiles` | 配置列表（分页、搜索、状态筛选） | 全部 |
| `POST` | `/configurations/profiles` | 创建配置 | admin, engineer |
| `GET` | `/configurations/profiles/{id}` | 详情 + 清单树 | 全部 |
| `PUT` | `/configurations/profiles/{id}` | 编辑基本信息 + 切换构型项 | admin, engineer |
| `DELETE` | `/configurations/profiles/{id}` | 删除（管理员可删任意状态） | admin |
| `PUT` | `/configurations/profiles/{id}/status` | 直接修改状态 | admin |
| `POST` | `/configurations/profiles/{id}/activate` | 生效（draft→active） | admin, engineer |
| `POST` | `/configurations/profiles/{id}/archive` | 归档（active→archived） | admin |
| `PUT` | `/configurations/profiles/{id}/items/{item_id}` | 勾选/取消单个零部件 | admin, engineer |
| `PUT` | `/configurations/profiles/{id}/config-items/{cid}/toggle` | 切换构型项节点及下属所有零部件 | admin, engineer |

### 5.2 详情接口返回结构

```json
{
  "id": "uuid",
  "code": "CFG-001",
  "name": "MSN001机翼方案",
  "status": "draft",
  "effectivity_start": "MSN001",
  "effectivity_end": "MSN050",
  "configuration_item": { "id": "uuid", "code": "CFG-WING", "name": "机翼构型" },
  "items": [
    {
      "id": "uuid", "item_code": "PART-001", "item_name": "襟翼",
      "item_type": "part", "item_version": "A", "item_status": "draft",
      "is_required": true, "is_selected": true,
      "source_config_item_id": "uuid", "source_type": "direct"
    }
  ],
  "config_tree": {
    "id": "uuid", "code": "CFG-WING", "name": "机翼构型",
    "is_required": true, "is_selected": true,
    "parts": [...],
    "children": [
      {
        "id": "uuid", "code": "CFG-SUB", "name": "缝翼构型",
        "is_required": false, "is_selected": true,
        "parts": [...], "children": [...]
      }
    ]
  }
}
```

> `config_tree` 为层级树形结构，前端直接渲染为配置清单表格。`item_version`、`item_status` 从零部件/部件表实时查询。

## 6. 前端设计

### 6.1 页面结构

```
Configuration.tsx
├── 构型项管理 Tab → ConfigurationList
│   ├── ConfigurationCreateModal（新建/编辑构型项+关联零部件+子构型项+图文档）
│   └── ConfigurationDetailModal（查看构型项详情）
│
└── 构型配置 Tab → ProfileList
    ├── ProfileEditModal（新建/查看/编辑配置）
    │   ├── 基本信息表单（编号/名称/架次/备注）
    │   ├── 状态管理（单选框，仅管理员+编辑模式）
    │   ├── 配置清单表格（层级/构型号/名称/类型/件号/版本/状态/可选）
    │   │   ├── 构型项行 → 显示构型号、名称、"构型项"标签
    │   │   ├── 零部件行 → 显示件号、版本、状态、名称
    │   │   ├── 折叠/展开（▶/▼）
    │   │   └── 关联构型项按钮（右上角，切换后重新生成清单）
    │   └── 正式配置清单（仅选中项，默认折叠，可展开）
    └── 删除确认弹窗（管理员可见）
```

### 6.2 配置清单表格

| 层级 | 构型号 | 名称 | 类型 | 零部件件号 | 版本 | 状态 | 可选 |
|------|--------|------|------|-----------|------|------|:--:|
| 0 | CFG-001 | 机翼构型 | `构型项` | - | - | - | ☑ 必选 |
| 0 | - | 襟翼 | `零件` | PART-001 | A | 草稿 | ☑ 必选 |
| ▶ -1 | CFG-010 | 缝翼构型 | `构型项` | - | - | - | ☐ 可选 |
| -1 | - | 主缝翼 | `部件` | ASSY-020 | B | 生效 | ☑ 必选 |

- 层级编号格式与部件子项列表一致：`0` → `-1` → `--2` → `---3`
- 构型项行有子项时显示 ▶/▼ 折叠箭头
- 折叠时同时隐藏零部件和子构型项
- 可选的构型项可整体勾选，联动切换下属所有零部件
- 零部件显示必选/可选标签
- 零部件状态显示中文（草稿/生效/归档）

### 6.3 正式配置清单

与配置清单相同的表格格式，仅显示已勾选的构型项和零部件，默认全部折叠，可逐层展开查看。

## 9. 设计决策

| 决策 | 理由 |
|------|------|
| 清单数据冗余存储 | 配置生效后构型项可能被修改，冗余可保证配置快照不变 |
| 架次用范围而非列表 | 生产批次以连续架次为主，范围可覆盖大部分场景 |
| 重新关联同构型项可重生成 | 避免早期 bug 数据残留，保证数据一致性 |
| 构型项可空 | 先建配置再关联构型项的灵活流程 |
| 管理员可删任意状态 | 生产环境中需要管理员兜底清理数据 |
| 状态单选框（仅管理员） | 替代逐步生效/归档按钮，提高效率 |
| 配置清单表格化 | 层级化展示对应构型项层级和零部件明细 |
| 必选件在节点 toggle 时可强制更新 | 可选构型项被勾选时下属所有零件（含必选件）统一勾选 |
