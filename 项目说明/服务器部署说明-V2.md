## 一、系统架构概览

### 1.1 服务组件

| 服务         | 容器名          | 技术栈                      | 端口映射                           |
| ---------- | ------------ | ------------------------ | ------------------------------ |
| Nginx      | bom_nginx    | nginx:alpine (HTTPS/TLS) | `${NGINX_HOST_PORT:-8080}:443` |
| FastAPI    | bom_backend  | Python 3.12 + FastAPI    | 内网（仅 Nginx 代理访问）               |
| PostgreSQL | bom_postgres | postgres:16-alpine       | `5432`（内网）                     |
| Redis      | bom_redis    | redis:7-alpine           | `6379`（内网）                     |

### 1.2 网络架构

```
浏览器 (HTTPS)
  └─→ nginx:443
       ├─ /            → /usr/share/nginx/html  (React SPA 静态文件)
       ├─ /api/        → backend:8000           (FastAPI 反向代理)
       └─ /health      → 200 OK                 (健康检查)
```

### 1.3 数据存储

| 数据            | 宿主机路径                             | 容器内路径                         | 配置变量                |
| ------------- | --------------------------------- | ----------------------------- | ------------------- |
| PostgreSQL 数据 | `${PGDATA_HOST_PATH:-./pgdata}`   | `/var/lib/postgresql/data`    | `PGDATA_HOST_PATH`  |
| 上传附件          | `${UPLOADS_HOST_PATH:-./uploads}` | `/app/uploads`                | `UPLOADS_HOST_PATH` |
| SSL 证书        | `./certs`                         | `/etc/nginx/certs`            | 固定路径                |
| 前端静态文件        | `./frontend/dist`                 | `/usr/share/nginx/html`       | 固定路径                |
| 数据库初始化脚本      | `./initdb`                        | `/docker-entrypoint-initdb.d` | 固定路径                |

### 1.4 环境变量（.env）

```bash
# === 端口与路径 ===
NGINX_HOST_PORT=8088                       # Nginx 宿主机映射端口
PGDATA_HOST_PATH=./pgdata                  # 数据库数据目录
UPLOADS_HOST_PATH=./uploads                # 附件存储目录

# === 安全密钥（必填，部署前生成随机值） ===
JWT_SECRET=<openssl rand -hex 32>          # JWT 签名密钥（64字符）
REDIS_PASSWORD=<openssl rand -base64 24>   # Redis 认证密码（32字符）

# === AI 助手配置（可选） ===
DEEPSEEK_API_KEY=sk-your-deepseek-api-key  # DeepSeek API Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
```

> **密钥生成**：参考 `.env.example` 注释，提供 Linux/Mac/Windows/Docker 四种生成方式。

## 二、本地测试环境部署

### 2.1 前提条件

- Windows 10/11 + Docker Desktop
- Node.js 18+（用于构建前端）
- PowerShell 5.1+
- 项目路径：`D:\OpenCode\myPDM`

### 2.2 目录准备

服务启动前需要确保以下目录结构存在：

```
D:\OpenCode\myPDM\
├── certs/               # SSL 证书（自签名）
├── frontend/dist/       # 前端构建输出
├── initdb/init.sql      # 数据库初始化脚本
├── nginx/nginx.conf     # Nginx 配置
├── docker-compose.yml
├── .env                 # 环境变量配置
├── uploads/             # 附件存储（自动创建）
└── pgdata/              # 数据库数据（自动创建）
```

### 2.3 一键部署

```powershell
# 1. 进入项目目录
cd D:\OpenCode\myPDM

# 2. 生成自签名证书（首次）
New-Item -ItemType Directory -Force -Path "certs"
openssl req -x509 -nodes -days 3650 -newkey rsa:2048 `
  -keyout certs/selfsigned.key `
  -out certs/selfsigned.crt `
  -subj "/C=CN/ST=Shanghai/L=Shanghai/O=myPDM/CN=localhost"

# 3. 配置 .env（从模板复制并填写密钥）
Copy-Item .env.example .env
# 编辑 .env，用 PowerShell 生成密钥：
#   JWT_SECRET  : -join ((48..57)+(65..90)+(97..122)|Get-Random -Count 64|%{[char]$_})
#   REDIS_PASSWORD: -join ((48..57)+(65..90)+(97..122)|Get-Random -Count 32|%{[char]$_})
#   将生成的值填入 .env 的对应项

# 4. 构建前端
cd frontend
npm install
npm run build
cd ..

# 5. 启动所有服务
docker compose up -d --build
```

### 2.4 访问

| 服务        | 地址                              | 说明               |
| --------- | ------------------------------- | ---------------- |
| 前端        | https://localhost:8080          | 浏览器需信任自签名证书      |
| 后端 API 文档 | https://localhost:8080/api/docs | Swagger UI       |
| 健康检查      | https://localhost:8080/health   | 返回 `ok`          |

> 后端不再暴露 8000 端口到宿主机，所有访问必须经过 Nginx HTTPS。

### 2.5 开发模式

后端代码通过 volume 挂载（`./backend/app:/app/app`），修改后重启容器即可：

```powershell
# 仅重启后端（代码修改后）
docker restart bom_backend

# 前端修改后需重新构建
cd frontend
npm run build
cd ..

# 前端构建后重启 Nginx
docker compose up -d --force-recreate nginx
```

### 2.6 停止/清理

```powershell
# 停止所有服务（保留数据）
docker compose down

# 彻底清理（删除数据库和附件）
docker compose down
Remove-Item -Recurse -Force pgdata, uploads
docker rmi mypdm-backend:latest
docker system prune -f
```

## 三、阿里云 ECS 部署

### 3.1 前提条件

- 阿里云 ECS（Ubuntu 22.04 / CentOS 7+）
- 安全组已开放 8080 端口（TCP）
- 有公网 IP（示例：`8.163.100.79`）
- 已安装 Git、Node.js 18+

### 3.2 安装 Docker

**Ubuntu 22.04：**

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
```

**CentOS 7+：**

```bash
sudo yum install -y yum-utils
sudo yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
```

### 3.3 配置 Docker 镜像加速

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://mirror.baidubce.com",
    "https://docker.1ms.run",
    "https://docker.1panel.live"
  ]
}
EOF
sudo systemctl daemon-reload
sudo systemctl restart docker
```

### 3.4 部署服务

```bash
# 1. 克隆项目
cd /opt
git clone https://github.com/guojunjiang-collab/myPDM.git
cd myPDM

# 2. 生成自签名证书
mkdir -p certs
MY_IP=$(curl -s ifconfig.me)
openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout certs/selfsigned.key \
  -out certs/selfsigned.crt \
  -subj "/C=CN/ST=Shanghai/L=Shanghai/O=myPDM/CN=$MY_IP"

# 3. 配置 .env 密钥
cp .env.example .env
# 编辑 .env，生成密钥：
#   JWT_SECRET=$(openssl rand -hex 32)
#   REDIS_PASSWORD=$(openssl rand -base64 24)
#   将命令输出的值填入 .env
sed -i "s/change-me-to-a-random-64-char-hex-string/$(openssl rand -hex 32)/" .env
sed -i "s/change-me-to-a-random-password/$(openssl rand -base64 24)/" .env

# 4. 构建前端
cd frontend
npm install
npm run build
cd ..

# 5. 启动所有服务
docker compose up -d --build
```

### 3.5 安全组配置

阿里云控制台 → ECS → 安全组 → 入方向规则：

| 协议  | 端口   | 来源        | 说明         |
| --- | ---- | --------- | ---------- |
| TCP | 8080 | 0.0.0.0/0 | HTTPS 前端访问 |

### 3.6 访问

浏览器打开：**https://<公网IP>:8080**

首次访问会提示证书不受信任 → 点击 **"高级" → "继续前往"** 即可。

### 3.7 配置可信证书（域名 + Let's Encrypt）

如果有域名：

```bash
# 安装 Certbot（Ubuntu）
sudo apt install -y certbot

# 获取证书（需域名已解析到服务器 IP）
sudo certbot certonly --standalone -d your-domain.com

# 复制证书
sudo cp /etc/letsencrypt/live/your-domain.com/fullchain.pem /opt/myPDM/certs/selfsigned.crt
sudo cp /etc/letsencrypt/live/your-domain.com/privkey.pem /opt/myPDM/certs/selfsigned.key

# 重启 Nginx
cd /opt/myPDM
docker compose up -d --force-recreate nginx
```

### 3.8 更新部署

```bash
cd /opt/myPDM

# 拉取最新代码
git pull

# 前端有变化 → 重新构建
cd frontend
npm install       # 仅依赖变更时需要
npm run build
cd ..

# 重启后端（代码通过 volume 挂载，重启即生效）
docker restart bom_backend

# Nginx 配置或前端有变更时重建
docker compose up -d --force-recreate nginx
```

## 四、NAS 部署（绿联云 / 飞牛）

### 4.1 NAS 部署特点

| 项目       | 说明                                              |
| -------- | ----------------------------------------------- |
| **核心问题** | NAS 文件系统有 ACL 权限限制，nginx 无法直接读取 volume 挂载的前端文件  |
| **解决方案** | 前端文件通过 Dockerfile COPY 打包进 Nginx 镜像             |
| **端口冲突** | NAS 管理界面占用 80/443 端口，myPDM 需使用其他端口（如 8080/8088） |
| **前端更新** | 每次前端修改必须 rebuild Nginx 镜像                       |
| **后端更新** | 后端代码通过 volume 挂载，重启容器即可                         |

### 4.2 绿联云 NAS（DXP4800PLUS）

#### 前提条件

- 绿联云 NAS 已安装 Docker
- SSH 已启用
- NAS 内网 IP：`192.168.1.53`

#### 首次部署步骤

```bash

# 2. 配置 Docker 镜像加速

{
  "registry-mirrors": [
    "https://docker.1ms.run",

  ]

# 5. 配置 .env 密钥

# 编辑 .env，填入 JWT_SECRET 和 REDIS_PASSWORD

#     JWT_SECRET=$(openssl rand -hex 32)
#     REDIS_PASSWORD=$(openssl rand -base64 24)
#   NAS 无 openssl 则在 PC 用 PowerShell 生成后粘贴

# 5. 创建 Nginx 专用 Dockerfile（解决 ACL 问题）
#    见下方 [NAS Nginx Dockerfile 配置]

#    见下方 [NAS docker-compose 适配]

# 8. 启动服务
docker compose up -d --build
```

#### NAS Nginx Dockerfile

创建 `Dockerfile.nginx`：

```dockerfile
FROM nginx:alpine
COPY frontend/dist /usr/share/nginx/html
COPY nginx/nginx.conf /etc/nginx/conf.d/default.conf
COPY certs /etc/nginx/certs
RUN chmod -R 755 /usr/share/nginx/html
```

#### NAS docker-compose 适配

将 `docker-compose.yml` 中 nginx 服务改为：

```yaml
  nginx:
    build:
      context: .
      dockerfile: Dockerfile.nginx
    container_name: bom_nginx
    volumes:
      - ./certs:/etc/nginx/certs
    # 注意：没有 ./frontend/dist 挂载行！
    depends_on:
      - backend
    networks:
      - bom_network
    ports:
      - "${NGINX_HOST_PORT:-8080}:443"
```

## 五、运维说明

### 5.1 日常命令速查

```bash
# === 服务管理 ===

# 启动所有服务

# 停止所有服务（保留数据）

# 完全重建（修改了 Dockerfile 或依赖）
docker-compose up -d --build

# === 日志查看 ===

# 后端日志
docker logs bom_backend -f --tail 100

# Nginx 日志
docker logs bom_nginx -f --tail 100

# PostgreSQL 日志
docker logs bom_postgres -f --tail 100

# === 进入容器 ===

# 后端容器
docker exec -it bom_backend bash

# PostgreSQL
docker exec -it bom_postgres psql -U bomadmin -d bom_system
```

### 5.2 数据库运维

#### 备份数据库

```bash
# 完整备份（SQL 文件）
docker exec bom_postgres pg_dump -U bomadmin bom_system > backup_$(date +%Y%m%d_%H%M%S).sql

# 仅备份表结构（不含数据）
docker exec bom_postgres pg_dump -U bomadmin --schema-only bom_system > schema_backup.sql

# 压缩备份
docker exec bom_postgres pg_dump -U bomadmin bom_system | gzip > backup.sql.gz
```

#### 恢复数据库

```bash
# 从 SQL 文件恢复
docker exec -i bom_postgres psql -U bomadmin -d bom_system < backup.sql

# 从压缩文件恢复
gunzip -c backup.sql.gz | docker exec -i bom_postgres psql -U bomadmin -d bom_system
```

#### 定时备份（Crontab）

```bash
# 每天凌晨 2 点备份，保留最近 30 天
crontab -e
```

添加：

```
0 2 * * * cd /opt/myPDM && docker exec bom_postgres pg_dump -U bomadmin bom_system | gzip > /opt/backups/bom_$(date +\%Y\%m\%d).sql.gz && find /opt/backups -name "bom_*.sql.gz" -mtime +30 -delete
```

### 5.3 附件备份

附件存储在 `${UPLOADS_HOST_PATH}`（默认 `./uploads/`）：

```bash
# 打包备份
tar -czf uploads_backup_$(date +%Y%m%d_%H%M%S).tar.gz uploads/

# 同步到远程
rsync -avz uploads/ user@backup-server:/path/to/backup/uploads/
```

### 5.4 完整恢复流程

**场景：新服务器从零恢复**

```bash
# 1. 克隆项目并部署基础服务
```

### 5.6 安全加固（v1.5.1+）

| 类别     | 措施                                    |
| ------ | ------------------------------------- |
| 传输加密   | Nginx HTTPS (TLSv1.2+)，安全头(HSTS/CSP/X-Frame) |
| 端口收敛   | 后端 8000 端口不暴露宿主机，仅 Nginx 代理         |
| 速率限制   | 登录接口 10r/s，API 30r/s，每 IP 20 并发       |
| 密钥管理   | JWT_SECRET / REDIS_PASSWORD 强随机生成，禁止默认值 |
| 文件安全   | 上传扩展名白名单，路径遍历防护，100MB 上限              |
| 容器安全   | 非 root 用户运行，Redis 密码认证                |
| 账号安全   | 部署后立即修改默认管理员密码，密码要求>=8位含大小写+数字        |
| 证书更新   | 自签名证书每 2 年更新一次；Let's Encrypt 自动续期     |
| 数据库    | 定期备份（建议每日），备份文件存储到异地                  |
| 防火墙    | 仅开放 Nginx 端口（8080），禁止直接暴露数据库/Redis/后端    |
| Docker | 定期更新基础镜像（`docker-compose pull`）       |
| 依赖更新   | 关注 Python/Node.js 依赖安全漏洞公告，及时更新       |
| API Key | DeepSeek Key 不与代码一起提交，通过 .env 注入       |

### 5.7 应急处理

#### 服务无法启动

```bash
# 1. 查看日志定位问题
docker-compose logs --tail 50

# 2. 检查端口占用
netstat -tlnp | grep -E "8080|8000|5432|6379"

# 3. 检查磁盘空间
df -h

# 4. 尝试逐个启动定位故障服务
docker-compose up -d postgres redis
docker-compose up -d backend
docker-compose up -d nginx
```

#### 数据库连接失败

```bash
# 检查 PostgreSQL 是否正常运行
docker exec bom_postgres pg_isready -U bomadmin

# 重启 PostgreSQL
docker restart bom_postgres
```

#### 磁盘空间不足

```bash
# 清理 Docker 未使用的资源
docker system prune -a -f

# 清理旧备份文件
find /opt/backups -name "bom_*.sql.gz" -mtime +60 -delete

# 检查大文件
du -sh uploads/* | sort -rh | head -20
```

## 六、常见问题

### 6.1 Docker 镜像拉取超时

使用国内镜像加速（见各部署章节）。

### 6.2 浏览器提示"不安全"

自签名证书不被浏览器信任，属于正常现象。点击"高级 → 继续前往"即可。如需消除警告，需配置域名 + Let's Encrypt 可信证书。

### 6.3 导入导出功能不可用

导入导出功能依赖浏览器 File System Access API，该 API 仅限 HTTPS 或 localhost。请确保通过 HTTPS 访问。

### 6.4 NAS 上 Nginx 403 Forbidden

NAS 文件系统 ACL 阻止 nginx 读取 volume 挂载的前端文件。解决方案：

- 使用 Dockerfile COPY 方式（见 [NAS 部署](#四nas-部署绿联云--飞牛)）
- **不要**使用 `./frontend/dist:/usr/share/nginx/html` 挂载

### 6.5 PostgreSQL 启动失败

```bash
# 通常是 initdb 权限问题
chmod -R 777 ./initdb
docker-compose down
docker-compose up -d
```

### 6.6 端口冲突

修改 `.env` 中的 `NGINX_HOST_PORT`：

```
NGINX_HOST_PORT=8088
```

然后执行 `docker-compose up -d` 重建容器。

### 6.7 前端修改后不生效

1. 确保已执行 `npm run build` 重新构建
2. 使用 Ctrl+F5 强制刷新浏览器（清除缓存）
3. 确认 Nginx 已重启：`docker-compose up -d --force-recreate nginx`
