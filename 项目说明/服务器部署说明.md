## 一、本地 Docker 开发部署

### 前提条件

- Windows 10/11 + Docker Desktop
- 项目路径：`D:\OpenCode\myPDM`

### 配置特点

本地开发使用 **volume 挂载** 方式加载前端文件，修改即时生效，无需重新 build。

### 部署步骤

```powershell
cd "D:\OpenCode\myPDM"
docker compose up -d --build
```

### 访问地址

| 服务     | 地址                         |
| ------ | -------------------------- |
| 前端     | http://localhost:8080      |
| 后端 API | http://localhost:8000/docs |

### docker-compose.yml 关键配置

```yaml
nginx:
  build:
    context: .
    dockerfile: Dockerfile.nginx
  volumes:
    - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf
    - ./frontend:/usr/share/nginx/html    # ← 前端文件挂载，修改即时生效
  ports:
    - "8080:80"
```

### 日常运维

```powershell
# 仅重建后端（代码修改后）
docker compose up -d --build backend

# 前端修改无需重启，刷新浏览器即可

# 重建 nginx（仅当 nginx 配置变更时）
docker compose up -d --build nginx

# 查看状态
docker ps --filter name=bom_

# 查看日志
docker logs -f bom_backend
```

### 停止/清理

```powershell
# 停止并删除容器（保留数据库）
docker compose down

# 彻底清理（数据库数据丢失）
docker compose down -v
```

## 二、绿联云 NAS 部署

### 前提条件

- 绿联云 NAS（DXP4800PLUS）
- 已安装 Docker
- 有 SSH 访问权限
- NAS 内网 IP：192.168.1.53

### 配置特点

NAS 的文件系统有 ACL 权限限制，nginx 无法通过 volume 挂载读取前端文件。因此采用 **Dockerfile COPY** 方式，将前端文件打包进镜像。

### 部署步骤

#### 1. SSH 登录

```bash
ssh root@192.168.1.53
```

#### 2. 配置 Docker 镜像加速

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}
EOF
sudo systemctl restart docker
```

#### 3. 克隆项目

```bash
mkdir -p /volume1/docker
cd /volume1/docker
git clone https://github.com/guojunjiang-collab/myPDM.git
cd myPDM
```

#### 4. 创建 nginx Dockerfile

```bash
cat > Dockerfile.nginx <<'EOF'
FROM nginx:alpine
COPY frontend /usr/share/nginx/html
COPY nginx/nginx.conf /etc/nginx/conf.d/default.conf
RUN chmod -R 755 /usr/share/nginx/html
EOF
```

#### 5. 修改 docker-compose.yml

**关键区别：去掉前端 volume 挂载，改用 Dockerfile COPY**

```bash
nano docker-compose.yml
```

将 nginx 服务改为：

```yaml
  nginx:
    build:
      context: .
      dockerfile: Dockerfile.nginx
    container_name: bom_nginx
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf
      # ← 注意：没有 ./frontend 挂载行
    depends_on:
      - backend
    networks:
      - bom_network
    ports:
      - "8080:80"    # 80 端口可能被 NAS 管理界面占用，改为 8080
```

#### 6. 设置 initdb 权限

```bash
chmod -R 777 ./initdb
```

#### 7. 启动服务

```bash
docker compose up -d --build
```

#### 8. 验证

浏览器打开：**http://192.168.1.53:8080**

默认管理员账号：`admin` / `admin123`

### ⚠️ NAS 部署注意事项

1. **端口冲突**：NAS 管理界面占用 80 端口，myPDM 改用 8080

2. **前端更新**：修改前端代码后必须重新 build nginx 镜像：
   
   ```bash
   docker compose up -d --build nginx
   ```

3. **后端更新**：修改后端代码后重新 build backend：
   
   ```bash
   docker compose up -d --build backend
   ```

4. **ACL 权限**：不要将 `./frontend:/usr/share/nginx/html` 加回 volume 挂载，NAS 的 ACL 会阻止 nginx 读取文件

### 外网访问配置

参考 [外网访问方案](#外网访问方案) 章节。

sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'

### HTTPS 配置（自签名证书）

导入导出功能依赖浏览器的 File System Access API，该 API 仅在 **HTTPS**（或 localhost）下可用。如果服务器没有域名，可以使用自签名证书。

#### 1. 拉取最新配置（含 HTTPS 支持）

```bash
cd /opt/myPDM
git pull
```

#### 2. 生成自签名证书

```bash
mkdir -p certs
MY_IP=$(curl -s ifconfig.me)
openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout certs/selfsigned.key \
  -out certs/selfsigned.crt \
  -subj "/C=CN/ST=Shanghai/L=Shanghai/O=myPDM/CN=$MY_IP"
```

#### 3. 构建前端

```bash
cd /opt/myPDM/frontend
npm install
npm run build
cd ..
```

#### 4. 启动服务

```bash
docker compose up -d --force-recreate nginx
```

#### 5. 安全组配置

阿里云控制台 → 安全组 → 添加入方向规则：

| 协议  | 端口   | 来源        | 说明                    |
| --- | ---- | --------- | --------------------- |
| TCP | 8080 | 0.0.0.0/0 | HTTPS 访问（与 HTTP 共用端口） |

> 如果之前有 8080 的 HTTP 规则，不需要删除——现在 8080 端口提供的是 HTTPS 服务。

### 关于 HTTPS 与自签名证书

#### 为什么导入导出功能需要 HTTPS？

导入导出功能使用浏览器 **File System Access API**（`showDirectoryPicker`），该 API 允许网页读写用户本地文件夹。出于安全考虑，所有主流浏览器都要求该 API **仅在 HTTPS（或 localhost）下可用**。

如果通过 HTTP 访问，`showDirectoryPicker` 为 `undefined`，系统会提示"您的浏览器不支持文件夹操作"。

#### 自签名证书安全吗？

自签名证书的**加密强度与付费证书完全相同**（均使用 TLS 1.2/1.3 + RSA 2048）。区别仅在于浏览器无法自动验证证书签发者，因此首次访问会显示警告页面。点击"继续前往"后，后续所有通信都是加密的，导入导出功能正常使用。

#### 能否配置真正的 HTTPS（无浏览器警告）？

需要有**域名**，然后可以使用 Let's Encrypt 获取免费可信证书：

```bash
# 安装 Certbot（以 CentOS 为例）
sudo yum install -y certbot python3-certbot-nginx

# 获取证书（需域名已解析到服务器 IP）
sudo certbot --nginx -d your-domain.com

# 自动续期
sudo certbot renew --dry-run
```

之后将证书文件挂载到 nginx 容器，修改 nginx.conf 使用可信证书即可。

## 四、常见问题

### 1. Docker Hub 拉取超时

配置镜像加速器：

```bash
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me"
  ]
}
EOF
sudo systemctl restart docker
```

### 2. 80 端口被占用

修改 `docker-compose.yml` 中的端口映射：

```yaml
ports:
  - "8080:80"    # 改为其他可用端口
```

### 3. NAS 上 403 Forbidden

NAS 文件系统有 ACL 限制，nginx 无法读取 volume 挂载的前端文件。解决方式：

- 使用 Dockerfile COPY 方式（见 NAS 部署步骤第 4-5 步）
- **不要**添加 `./frontend:/usr/share/nginx/html` 挂载

### 4. PostgreSQL 启动失败（Permission denied）

```bash
chmod -R 777 /path/to/myPDM/initdb
docker compose down
docker compose up -d
```

### 5. 查看日志

```bash
docker logs bom_backend --tail 50
docker logs bom_nginx --tail 50
docker logs bom_postgres --tail 50
```

## 外网访问方案

### 方案 A：路由器端口转发（推荐）

1. 登录路由器管理界面
2. 添加端口转发：外部端口 → 内网 IP:8080
3. 获取公网 IP：`curl ifconfig.me`
4. 外网访问：`http://公网IP:外部端口`

### 方案 B：FRP 内网穿透（无公网 IP）

需要一台有公网 IP 的 VPS。

**VPS 端：**

```bash
wget https://github.com/fatedier/frp/releases/download/v0.61.1/frp_0.61.1_linux_amd64.tar.gz
tar -xzf frp_0.61.1_linux_amd64.tar.gz && cd frp_0.61.1_linux_amd64

cat > frps.toml <<EOF
bindPort = 7000
auth.token = "your_password_here"
EOF

./frps -c frps.toml
```

**NAS 端：**

```bash
wget https://github.com/fatedier/frp/releases/download/v0.61.1/frp_0.61.1_linux_arm64.tar.gz
tar -xzf frp_0.61.1_linux_arm64.tar.gz && cd frp_0.61.1_linux_arm64

cat > frpc.toml <<EOF
serverAddr = "VPS公网IP"
serverPort = 7000
auth.token = "your_password_here"

[[proxies]]
name = "my-pdm"
type = "http"
localIP = "127.0.0.1"
localPort = 8080
customDomains = ["pdm.你的域名.com"]
EOF

./frpc -c frpc.toml
```

### 方案 C：Tailscale 组网（安全简单）

1. NAS 和客户端都安装 Tailscale
2. 同一账号登录
3. 通过 Tailscale IP 访问

## 配置对比

| 项目       | 本地 Docker        | 绿联云 NAS          | 阿里云 ECS            |
| -------- | ---------------- | ---------------- | ------------------ |
| 前端加载方式   | volume 挂载        | Dockerfile COPY  | volume 挂载          |
| 前端修改后    | 刷新即生效            | 需 rebuild nginx  | 刷新即生效              |
| 端口       | 8080 → 80 (HTTP) | 8080 → 80 (HTTP) | 8080 → 443 (HTTPS) |
| 外网访问     | 不需要              | 需配置              | 直接访问               |
| ACL 权限问题 | 无                | 有                | 无                  |
| 导入导出功能   | 支持（localhost）    | 需 HTTPS 配置       | 支持（已配 HTTPS）       |
| 默认账号     | admin / admin123 | admin / admin123 | admin / admin123   |

- 建议配置 HTTPS（Nginx + Let's Encrypt / Certbot）
- 建议定期备份 PostgreSQL 数据库
