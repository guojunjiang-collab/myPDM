# 附件压缩包预览 —— 设计方案

> **状态**: 已实现  
> **创建**: 2026-05-09  
> **更新**: 2026-05-14  
> **目标**: 实现 ZIP / TAR / TAR.GZ / RAR / 7Z 压缩包的内容预览，展示内部文件夹层级，支持单个文件提取下载/预览

---

## 一、需求概述

在附件管理中，用户上传压缩包后，点击"预览"应能看到压缩包内部的文件夹层级和文件列表，无需下载或解压。同时支持对压缩包内单个文件的提取下载和预览。

## 二、支持格式

| 格式 | 扩展名 | 后端依赖 | 新增 pip 依赖 | 系统依赖 |
|------|--------|----------|--------------|----------|
| ZIP | `.zip` | `zipfile`（Python 标准库） | 无 | 无 |
| TAR | `.tar` | `tarfile`（Python 标准库） | 无 | 无 |
| TAR.GZ | `.tar.gz` `.tgz` | `tarfile`（Python 标准库） | 无 | 无 |
| RAR | `.rar` | `rarfile`（pip） | `rarfile==4.2` | `unrar`（apt non-free） |
| 7Z | `.7z` | `py7zr`（pip） | `py7zr==0.21.0` | 无 |

## 三、后端 API

### 3.1 `GET /api/v2/attachments/{id}/archive-tree`

**功能**：读取压缩包内容，返回内部文件夹/文件树形结构。

**参数**：

| 参数 | 位置 | 类型 | 说明 |
|------|------|------|------|
| `{id}` | path | UUID | 附件 ID |
| `token` | query | string | JWT 认证令牌 |

**权限**：`guest` 不可访问，`production` 及以上可访问。

**处理逻辑**：

1. JWT 验证 → 权限检查（复用 `/preview` 端点的认证逻辑）
2. 从 `document_attachments` 表查附件记录
3. 根据 `file_name` 扩展名判断压缩格式（`.zip` → `zipfile`，`.rar` → `rarfile`，`.7z` → `py7zr`，`.tar/.tar.gz/.tgz` → `tarfile`）
4. 打开压缩包，遍历所有条目，收集文件名、类型（文件/目录）、大小
5. 调用树构建算法：按路径排序 → 逐层创建目录节点 → 文件挂到对应目录下
6. 返回 JSON：`{ file_name, total_files, total_size, tree: [...] }`

**响应结构**：

```json
{
  "file_name": "设计图纸.zip",
  "total_files": 142,
  "total_size": 10485760,
  "tree": [
    {
      "name": "BOM.xlsx",
      "path": "BOM.xlsx",
      "type": "file",
      "size": 128000
    },
    {
      "name": "机械部分",
      "type": "dir",
      "size": 0,
      "children": [
        {
          "name": "主轴.dwg",
          "path": "机械部分/主轴.dwg",
          "type": "file",
          "size": 2048000
        }
      ]
    }
  ]
}
```

**树节点字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 文件/目录名（不含路径） |
| `path` | string | 压缩包内完整路径（仅文件节点） |
| `type` | string | `"file"` 或 `"dir"` |
| `size` | number | 文件大小（字节），目录为 0 |
| `compressed_size` | number | 压缩后大小（可选，ZIP/RAR 有） |
| `children` | array | 子节点（目录有，递归嵌套） |

### 3.2 `GET /api/v2/attachments/{id}/extract-file`

**功能**：从压缩包中提取单个文件并返回（下载或预览）。

**参数**：

| 参数 | 位置 | 类型 | 说明 |
|------|------|------|------|
| `{id}` | path | UUID | 附件 ID |
| `path` | query | string | 压缩包内文件路径（需 URL 编码） |
| `token` | query | string | JWT 认证令牌 |
| `disposition` | query | string | `"attachment"`（下载）或 `"inline"`（预览） |

**权限**：与 `/archive-tree` 相同。

**处理逻辑**：

1. JWT 验证 → 权限检查
2. 从 `document_attachments` 表查附件记录
3. 根据 `file_name` 扩展名判断压缩格式
4. 打开压缩包，按 `path` 参数匹配对应文件条目（路径规范化处理：统一用 `/`，去首尾 `/`）
5. 提取文件到临时目录（`tempfile.mkdtemp`）
6. 返回 `FileResponse`，`Content-Disposition` 按 `disposition` 参数设置
7. 临时文件由操作系统清理

**`disposition` 取值**：

| 值 | 场景 | 浏览器行为 |
|------|------|-----------|
| `attachment` | 下载 | 弹出保存对话框 |
| `inline` | 预览 | 新标签页内嵌显示（PDF、图片等） |

**错误处理**：

- 路径不存在 → `404`（`"文件不存在: {path}"`）
- 非压缩包 → `400`
- 提取异常 → `500`

## 四、前端组件

### 4.1 预览入口（扩展）

涉及两个文件的 `handlePreview` / `handlePreviewAttachment` 函数：

| 文件 | 说明 |
|------|------|
| `DocumentDetailContent.tsx` | 图文档详情页的附件预览 |
| `EntityDocumentSection.tsx` | 零件/部件详情中关联文档的预览 |

**逻辑**：

1. 从文件名获取扩展名
2. 若为 `pdf` → 保持原有行为：`window.open(/preview)` 浏览器内嵌预览
3. 若为 `zip / tar / gz / tgz / rar / 7z` → 设置 `archivePreview` 状态，弹出 `ArchiveTreeModal`
4. 其他格式 → `alert("该格式暂不支持预览")`

### 4.2 `ArchiveTreeModal`（压缩包树形预览弹窗）

**组件位置**：`frontend/src/components/ArchiveTreeModal.tsx`

**触发方式**：预览入口判断为压缩包格式时弹出此 Modal。

**数据加载**：

1. Modal 打开时，通过 `useAuthStore` 获取当前 JWT token
2. 调用 `attachmentApi.archiveTree(attachmentId, token)` → `GET /archive-tree`
3. 显示加载中 / 错误 / 树形数据三种状态

**树形展示**：

- **表头**：名称 | 大小 | 操作
- **目录行**：可点击展开/折叠（▶/▼），显示 📁 图标
- **文件行**：不可点击，显示 📄 图标 + 文件大小
- **嵌套缩进**：每层缩进 20px
- **首层默认展开**，子层默认折叠
- 顶部显示总文件数和总大小

**操作列**：

| 按钮 | 可见条件 | 行为 |
|------|---------|------|
| 下载 | 所有文件 | 新标签页打开 `/extract-file?path={完整路径}&disposition=attachment` |
| 预览 | 可预览文件类型（PDF、图片、文本、STP 等） | 新标签页打开 `/extract-file?path={完整路径}&disposition=inline` |

**文件路径处理**：发送请求时使用 `node.path`（压缩包内完整路径），若缺失则回退到 `node.name`。

**可预览类型判定**（前端）：
- 扩展名为 `pdf`, `png`, `jpg`, `jpeg`, `gif`, `bmp`, `svg`, `txt`, `md`, `csv`, `json`, `xml`, `stp`, `step` 的文件显示「预览」按钮
- 其他文件仅显示「下载」按钮（如 `.dwg`, `.docx`, `.xlsx` 等）

## 五、核心后端模块

### 5.1 `archive_reader.py`

**位置**：`backend/app/bom/archive_reader.py`

**对外接口**：

| 函数 | 功能 | 输入 | 输出 |
|------|------|------|------|
| `read_archive_tree(file_path)` | 读取压缩包内容树 | 文件路径 | `{ tree, total_files, total_size }` |
| `extract_file(archive_path, file_path_in_archive)` | 提取单个文件 | 压缩包路径 + 内部文件路径 | 临时文件路径 |
| `SUPPORTED_EXTENSIONS` | 支持的扩展名集合 | — | `{'.zip','.tar','.gz','.tgz','.rar','.7z'}` |

**内部读取器**（分格式）：

| 函数 | 格式 | 依赖 |
|------|------|------|
| `_read_zip()` | ZIP | `zipfile.ZipFile` |
| `_read_tar()` | TAR / TAR.GZ | `tarfile.open(mode='r:*')` 自动检测压缩 |
| `_read_rar()` | RAR | `rarfile.RarFile`（需系统 `unrar`） |
| `_read_7z()` | 7Z | `py7zr.SevenZipFile` |

**树构建算法**（`_build_tree`）：

1. 按路径排序所有条目（父目录在子文件前）
2. 遍历条目，将路径按 `/` 分割
3. 逐层检查目录前缀是否已存在：
   - 不存在 → 创建目录节点，挂到父目录的 `children` 数组
   - 存在 → 跳过
4. 文件节点创建后挂到对应父目录的 `children` 数组
5. 维护 `dir_map`（路径前缀 → 目录节点）映射表，支持 O(1) 查找父节点

### 5.2 `attachments_v2.py` — 新增端点

**位置**：`backend/app/routers/attachments_v2.py`

在原有上传/下载/预览/删除端点基础上，新增两个端点：

| 端点 | 方法 | 行号 | 说明 |
|------|------|------|------|
| `/archive-tree` | GET | ~607 | 压缩包内容树 |
| `/extract-file` | GET | ~681 | 单个文件提取 |

两个端点共用相同的 JWT 认证和权限校验逻辑（从 `/preview` 端点复用）。

## 六、前后端交互流程

### 6.1 压缩包预览流程

```
用户点击"预览"按钮 (.zip 附件)
  ↓
前端 handlePreview() 判断扩展名
  ↓
前端 setArchivePreview({ attId, fileName })
  ↓
ArchiveTreeModal 打开，useEffect 触发
  ↓
前端 GET /api/v2/attachments/{id}/archive-tree?token=
  ↓
后端 JWT 验证 → 查附件 → 判断格式 → read_archive_tree()
  ↓
后端返回 JSON 树 { file_name, total_files, total_size, tree }
  ↓
前端渲染 Modal: 总览统计 + 递归树形表格
```

### 6.2 文件下载/预览流程

```
用户在压缩包树中点击某文件的"下载"或"预览"
  ↓
前端构造 URL: /api/v2/attachments/{id}/extract-file?path={完整路径}&token=&disposition=
  ↓
window.open(url, '_blank') 新标签页
  ↓
后端 JWT 验证 → 查附件 → extract_file(压缩包路径, 内部路径)
  ↓
后端提取到临时目录 → FileResponse 返回
  ↓
浏览器根据 disposition 决定下载或内嵌显示
```
