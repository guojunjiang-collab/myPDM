# PDM系统 核心数据导入导出功能设计方案

## 一、需求总览

实现零件、部件、图文档三大核心数据的完整导入导出，支持定期数据备份和迁移恢复。

### 导出需求

| 数据 | 导出内容 | 格式 |
|------|---------|------|
| 零件 | 全部字段 + 关联图文档列表 | Excel |
| 部件列表 | 全部部件（不含子项） | Excel |
| 部件BOM | 每个部件的完整BOM树（多级子项） | 每个部件一个 Excel 文件 |
| 图文档 | 全部字段 + 附件文件（含实体文件） | Excel + 附件文件夹 |

### 导入需求

| 数据 | 导入内容 | 说明 |
|------|---------|------|
| 零件 | 全部字段 + 关联图文档编号 | 按件号+版本匹配，有则更新，无则新增 |
| 部件 | 多个顶层部件 + 每个部件的BOM子项 | 导出的反向操作 |
| 图文档 | 全部字段 + 附件文件（含实体文件） | 元数据 + 附件文件一起导入 |

## 二、导出详细设计

### 2.1 零件导出

**触发**：零件管理页面顶部「📥 导出Excel」按钮

**输出文件**：`零件清单_YYYYMMDD.xlsx`，单文件，包含以下 Sheet：

| Sheet名 | 内容 | 列 |
|---------|------|-----|
| 零件数据 | 所有零件 | 零件件号、中文名称、规格型号、版本、状态、创建时间、更新时间、自定义字段... |
| 关联图文档 | 零件-图文档关系 | 零件件号、零件版本、图文档编号、图文档名称、图文档版本 |

## 三、导入详细设计

### 3.1 零件导入

**输入**：单个 Excel 文件（与导出的 `零件清单.xlsx` 格式一致）

**流程**：

```
上传 Excel → 解析 Sheet"零件数据"
  ├── 校验必填字段（件号、名称）
  ├── 按 件号+版本 匹配本地数据
  │     ├── 匹配到 → 标记为"更新"
  │     └── 未匹配 → 标记为"新增"
  ├── 解析 Sheet"关联图文档"
  │     └── 关联关系待零件创建/更新后再处理
  └── 显示预览（含状态标记：新增/更新/错误）
      └── 用户确认 → 批量创建/更新零件 → 建立关联关系
```

**关联图文档处理**：
- Excel 中填的是图文档编号+版本
- 系统按编号+版本查找已有图文档
- 找不到的标记为"未找到"警告，跳过该关联

### 3.2 部件导入

**输入**：一个 ZIP 文件（与导出的 `部件数据.zip` 结构一致）

**流程**：

```
上传 ZIP → 解压
  ├── 解析"部件清单.xlsx"
  │     ├── 校验必填字段
  │     ├── 按 件号+版本 匹配 → 标记新增/更新
  │     └── 显示预览
  └── 解析每个"BOM_xxx.xlsx"
        ├── 按文件名匹配部件件号
        ├── 解析BOM树结构（层级、类型、件号、用量）
        └── 递归构建子项关系
  └── 用户确认 → 批量创建/更新部件 → 建立BOM关系
```

**BOM 子项处理**：
- 每行子项按 件号 查找已有零件/部件
- 找不到的标记为"未找到"警告
- 按层级关系递归建立父子关系

### 3.3 图文档导入

**输入**：一个 ZIP 文件（与导出的 `图文档数据.zip` 结构一致）

**流程**：

```
上传 ZIP → 解压
  ├── 解析"图文档清单.xlsx"
  │     ├── 校验必填字段（编号、名称）
  │     ├── 按 编号+版本 匹配 → 标记新增/更新
  │     └── 显示预览
  ├── 从 attachments/ 中匹配附件文件
  │     └── 按文件名前缀（图文档编号_v版本）匹配图文档记录
  └── 用户确认 → 批量创建/更新图文档 → 上传附件文件
```

**附件上传处理**：
- 前端逐个读取附件文件
- 通过现有分块上传 API 上传到后端
- 关联到对应的图文档记录
- 单文件超过 100MB 提示警告（防止误传大文件）

## 四、技术方案

### 4.1 依赖库

| 库 | 用途 | 大小 |
|----|------|------|
| SheetJS（xlsx） | Excel 读写 | ~500KB |
| JSZip | ZIP 压缩/解压（部件和图文档导出） | ~100KB |

均通过 CDN 或本地 `lib/` 目录引入，**纯前端方案，后端零改动**。

### 4.2 新增前端文件

```
frontend/js/
  ├── lib/
  │   ├── xlsx.min.js          ← SheetJS
  │   └── jszip.min.js         ← JSZip
  └── import-export.js          ← 导入导出核心逻辑
```

### 4.3 `import-export.js` 模块结构

```
ImportExport = {
  // === 导出 ===
  exportParts()                          零件导出（Excel，含关联图文档Sheet）
  exportAllAssemblies()                  部件全部导出（ZIP：清单 + 每个部件BOM）
  exportAssemblyBom(compId)              单个部件BOM导出（Excel）
  exportDocuments()                      图文档导出（ZIP：清单 + 附件文件夹）

  // === 导入 ===
  importParts(file, onPreview, onConfirm)              零件导入
  importAssemblies(zipFile, onPreview, onConfirm)      部件导入（ZIP）
  importDocuments(zipFile, onPreview, onConfirm)      图文档导入（ZIP + 附件）

  // === 模板 ===
  downloadTemplate(type)                下载导入模板（空Excel/ZIP）

  // === 通用 ===
  _parseExcel(file)                      解析 Excel 文件 → JSON
  _createZip(files)                      创建 ZIP 文件
  _readZip(zipFile)                      读取 ZIP 文件
  _batchCreate(items, type)             批量创建/更新
}
```

## 七、注意事项

1. **导入不删除**：导入只做新增和更新，不会删除已有数据
2. **冲突处理**：按 件号+版本 匹配，匹配到则更新（覆盖），未匹配则新增
3. **附件大小**：导入附件时单文件超过 100MB 给出警告
4. **导入上限**：单次导入上限 500 条主记录
5. **编码**：Excel 使用 UTF-8，文件名避免特殊字符
6. **断点续传**：大文件附件使用现有分块上传机制
7. **后端零改动**：所有导入导出在前端完成，通过现有 API 操作
8. **ZIP 结构约定**：导出的 ZIP 文件夹名带日期，方便按时间归档
