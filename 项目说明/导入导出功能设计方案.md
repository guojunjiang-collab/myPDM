# 零部件与图文档导入导出功能设计方案

## 一、现状分析

### 已有能力

| 功能 | 位置 | 格式 | 说明 |
|------|------|------|------|
| 零件导出 | 零件管理页面顶部按钮 | CSV | 导出全部零件，含自定义字段，前端生成 |
| 部件BOM导出 | 部件列表每行"导出"按钮 | CSV | 导出单个部件的BOM树（含子项），前端生成 |
| 图文档导出 | 无 | — | — |
| 零件导入 | 无 | — | — |
| 部件导入 | 无 | — | — |
| 图文档导入 | 无 | — | — |

### 技术基础

- **前端导出工具**：`UI.exportCSV(data, filename, columns)` — 通用CSV生成，支持列渲染函数
- **前端解析工具**：无（需新增Excel/CSV解析能力）
- **后端文件处理**：已有文件上传能力（`DocumentAttachment`），支持本地文件系统存储
- **数据模型**：零件/部件/图文档均有 code+version 唯一约束
- **自定义字段**：支持 `customFields` JSONB，可按 `applies_to` 区分 part/component/document

### 存在的问题

1. 零件导出只有 CSV，不支持 Excel（.xlsx）
2. 没有 Excel 解析能力，无法实现导入
3. 部件只有单个BOM导出，没有批量导出
4. 图文档完全没有导入导出能力

## 二、功能规划

### 2.1 零件管理

| 功能 | 描述 |
|------|------|
| 导出 Excel | 将现有 CSV 导出升级为 Excel（.xlsx），保留自定义字段 |
| 导入 Excel | 按模板导入零件数据，支持批量新增和更新（按 件号+版本 匹配） |

### 2.2 部件管理

| 功能 | 描述 |
|------|------|
| 批量导出 | 顶部新增"导出全部"按钮，导出所有部件列表（不含BOM子项） |
| 导出 Excel | 将现有 CSV 导出升级为 Excel |
| 单个BOM导出 | 保留现有功能，升级为 Excel |
| 导入 Excel | 按模板导入部件数据，支持批量新增和更新 |

### 2.3 图文档管理

| 功能 | 描述 |
|------|------|
| 导出 Excel | 导出图文档列表（编号、名称、版本、状态、描述等） |
| 导入 Excel | 按模板导入图文档元数据（不含附件文件） |

## 三、技术方案

### 3.1 技术选型

| 能力 | 方案 | 说明 |
|------|------|------|
| Excel 生成（导出） | **前端 `xlsx`（SheetJS）** | 轻量，浏览器端生成，无需后端 |
| Excel 解析（导入） | **前端 `xlsx`（SheetJS）** | 同上，一个库同时解决导入导出 |
| 文件大小 | 无特殊限制 | Excel 导入通常几百行，不会超 1GB 限制 |

> 选择纯前端方案：无需后端改动，开发快，对现有架构零侵入。

### 3.2 导入模板设计

每种数据类型提供一个标准 Excel 模板，用户可先"下载模板"，填写后再上传。

#### 零件导入模板

| 列 | 字段 | 必填 | 说明 |
|----|------|:----:|------|
| A | 零件件号 | ✅ | 导入时按件号+版本匹配：有则更新，无则新增 |
| B | 中文名称 | ✅ | |
| C | 规格型号 | | |
| D | 版本 | | 默认 A |
| E | 状态 | | 草稿/冻结/发布/作废，默认草稿 |
| F+ | 自定义字段 | | 动态列，按自定义字段定义自动追加 |

#### 部件导入模板

| 列 | 字段 | 必填 | 说明 |
|----|------|:----:|------|
| A | 部件件号 | ✅ | |
| B | 中文名称 | ✅ | |
| C | 规格型号 | | |
| D | 版本 | | 默认 V1.0 |
| E | 状态 | | 草稿/冻结/发布/作废，默认草稿 |
| F+ | 自定义字段 | | 动态列 |

#### 图文档导入模板

| 列 | 字段 | 必填 | 说明 |
|----|------|:----:|------|
| A | 图文档编号 | ✅ | |
| B | 名称 | ✅ | |

### 3.3 导入流程

```
用户点击"导入" → 弹出导入对话框
  ├── ① 下载模板（生成带列头的空 Excel）
  ├── ② 上传 Excel 文件
  ├── ③ 前端解析 + 数据校验
  │     ├── 必填字段检查
  │     ├── 件号+版本唯一性预检（对比本地缓存）
  │     ├── 状态值合法性检查
  │     └── 生成预览表格（显示校验结果）
  └── ④ 用户确认 → 批量调用后端 API 创建/更新
        ├── 新增条目：POST /api/parts 或 /api/assemblies 或 /api/documents
        ├── 更新条目：PUT /api/parts/{id} 或 /api/assemblies/{id} 或 /api/documents/{id}
        └── 显示结果摘要（成功 N 条，失败 M 条）
```

### 3.4 导出流程

```
用户点击"导出" → 前端收集数据 → xlsx 生成 Excel → 浏览器下载
```

### 3.5 前端文件结构

```
frontend/js/
  ├── lib/
  │   └── xlsx.min.js          ← SheetJS 库（CDN 或本地）
  ├── import-export.js          ← 新增：导入导出通用逻辑
  │   ├── ImportExport.generateTemplate(type)     生成导入模板
  │   ├── ImportExport.importFromFile(type, file) 解析并导入
  │   ├── ImportExport.exportToExcel(type, data)  导出为 Excel
  │   └── ImportExport._validateRows(rows, type)  数据校验
  ├── pages-parts.js            ← 添加"导入"按钮
  ├── pages-components.js       ← 添加"导入"+"导出全部"按钮
  └── pages-documents.js        ← 添加"导入"+"导出"按钮
```

|------|:-----:|:--------:|:----------:|:-----:|

## 六、注意事项

1. **导入不删除**：导入只做新增和更新，不会删除已有数据
2. **冲突处理**：按 件号+版本 匹配，匹配到则更新（覆盖），未匹配则新增
3. **附件不导入**：图文档导入仅导入元数据，附件需在导入后单独上传
4. **自定义字段**：导入模板动态包含当前已定义的自定义字段
5. **后端无需改动**：导入/导出均在前端完成，通过现有 API 批量操作
6. **大数量保护**：单次导入上限 500 条，超限需分批
