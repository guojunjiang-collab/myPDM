# PDM系统 核心数据导入导出功能设计方案

## 一、需求总览

实现零件、部件、图文档三大核心数据的完整导入导出，支持定期数据备份和迁移恢复。

### 导出需求

| 数据 | 导出内容 | 格式 |
|------|---------|------|
| 零件 | 全部字段 + 关联图文档列表 | 单个 Excel 文件 |
| 部件列表 | 全部部件（不含子项） | Excel 文件 |
| 部件BOM | 每个部件的完整BOM树（多级子项） | 文件夹：清单 + 每个部件一个 Excel |
| 图文档 | 全部字段 + 附件文件（含实体文件） | 文件夹：清单 + 附件子文件夹 |

### 导入需求

| 数据 | 导入内容 | 说明 |
|------|---------|------|
| 零件 | 全部字段 + 关联图文档编号 | 按件号+版本匹配，有则更新，无则新增 |
| 部件 | 多个顶层部件 + 每个部件的BOM子项 | 选择导出的文件夹，反向还原 |
| 图文档 | 全部字段 + 附件文件（含实体文件） | 选择导出的文件夹，元数据+附件一起导入 |

## 二、导出详细设计

### 2.1 零件导出

**触发**：零件管理页面顶部「📥 导出Excel」按钮

**输出**：单个文件 `零件清单_YYYYMMDD.xlsx`，包含以下 Sheet：

| Sheet名 | 内容 | 列 |
|---------|------|-----|
| 零件数据 | 所有零件 | 零件件号、中文名称、规格型号、版本、状态、创建时间、更新时间、自定义字段... |
| 关联图文档 | 零件-图文档关系 | 零件件号、零件版本、图文档编号、图文档名称、图文档版本 |

> 零件件号本身含版本唯一约束，不会重名，无需在文件名中加版本。

**下载方式**：浏览器直接下载（与现有方式相同）

## 三、导入详细设计

### 3.1 零件导入

**输入**：单个 Excel 文件（与导出的 `零件清单.xlsx` 格式一致）

**流程**：

```
上传 Excel → 解析 Sheet"零件数据"
  ├── 校验必填字段（件号、名称）
  ├── 按 件号+版本 匹配本地数据
  │     ├── 匹配到 → 标记为"更新"
  │     └── 未匹配 → 标记为"新增"
  ├── 解析 Sheet"关联图文档"
  │     └── 关联关系待零件创建/更新后再处理
  └── 显示预览（含状态标记：新增/更新/错误）
      └── 用户确认 → 批量创建/更新零件 → 建立关联关系
```

**关联图文档处理**：
- Excel 中填的是图文档编号+版本
- 系统按编号+版本查找已有图文档
- 找不到的标记为"未找到"警告，跳过该关联

### 3.2 部件导入

**输入**：用户选择一个文件夹（与导出结构一致）

**流程**：

```
用户选择文件夹 → 扫描目录结构
  ├── 查找"部件清单.xlsx" → 解析部件列表
  │     ├── 校验必填字段
  │     ├── 按 件号+版本 匹配 → 标记新增/更新
  │     └── 显示预览
  ├── 查找所有"BOM_*.xlsx" → 解析每个部件的BOM树
  │     ├── 按文件名提取部件件号和版本（如 `BOM_ASM-001_V2.0.xlsx` → 件号=ASM-001, 版本=V2.0）
  │     ├── 解析BOM树结构（层级、类型、件号、用量）
  │     └── 递归构建子项关系
  └── 用户确认 → 批量创建/更新部件 → 建立BOM关系
```

**BOM 子项处理**：
- 每行子项按 件号 查找已有零件/部件
- 找不到的标记为"未找到"警告
- 按层级关系递归建立父子关系

### 3.3 图文档导入

**输入**：用户选择一个文件夹（与导出结构一致）

**流程**：

```
用户选择文件夹 → 扫描目录结构
  ├── 查找"图文档清单.xlsx" → 解析图文档列表
  │     ├── 校验必填字段（编号、名称）
  │     ├── 按 编号+版本 匹配 → 标记新增/更新
  │     └── 显示预览
  ├── 扫描 attachments/ 子文件夹中的文件
  │     └── 按文件名前缀（编号_v版本）匹配图文档记录
  └── 用户确认 → 批量创建/更新图文档 → 上传附件文件
```

**附件上传处理**：
- 前端逐个读取附件文件
- 通过现有分块上传 API 上传到后端
- 关联到对应的图文档记录
- 单文件超过 1GB 给出警告

## 四、技术方案

### 4.1 浏览器文件夹操作

使用 **File System Access API** 实现文件夹读写：

| API | 用途 | 浏览器支持 |
|-----|------|-----------|
| `showDirectoryPicker()` | 导出时让用户选择保存文件夹 | Chrome 86+, Edge 86+ |
| `showOpenFilePicker()` | 导入时让用户选择文件夹 | Chrome 86+, Edge 86+ |
| `FileSystemDirectoryHandle` | 读写文件夹中的文件 | 同上 |

**降级方案**：若浏览器不支持 File System Access API，退回为 ZIP 下载/上传方式。

### 4.2 依赖库

| 库 | 用途 | 大小 | 下载方式 |
|----|------|------|---------|
| SheetJS（xlsx） | Excel 读写 | ~500KB | CDN / 本地 lib/ |
| JSZip | ZIP 降级方案 | ~100KB | CDN / 本地 lib/ |

### 4.3 新增前端文件

```
frontend/js/
  ├── lib/
  │   ├── xlsx.min.js          ← SheetJS
  │   └── jszip.min.js         ← JSZip（降级用）
  └── import-export.js          ← 导入导出核心逻辑
```

### 4.4 `import-export.js` 模块结构

```
ImportExport = {
  // === 导出 ===

  exportAssemblyBom(compId)                  单个部件BOM导出（Excel，保留现有功能）
  exportDocuments()                          图文档导出（文件夹：清单 + 附件）

  // === 模板 ===
```

### 4.5 文件夹导出流程（详细）

```javascript
// 以部件导出为例
async exportAllAssemblies() {
  // 1. 检测 API 支持
  if (!window.showDirectoryPicker) {
    // 降级：提示用户使用 Chrome/Edge，或使用 ZIP 方式
    UI.alert('请使用 Chrome 或 Edge 浏览器以支持文件夹导出');
    return;
  }

  // 2. 用户选择保存位置
  const dirHandle = await window.showDirectoryPicker({ mode: 'readwrite' });
  const folderName = '部件数据_' + today();
  const subDir = await dirHandle.getDirectoryHandle(folderName, { create: true });

  // 3. 生成并写入部件清单
  const listWb = buildAssemblyListWorkbook();
  const listBlob = xlsx.write(listWb, { type: 'blob', bookType: 'xlsx' });
  await writeFile(subDir, '部件清单.xlsx', listBlob);

  // 4. 生成并写入每个部件的 BOM
  for (const comp of components) {
    const bomWb = buildBomWorkbook(comp);
    const bomBlob = xlsx.write(bomWb, { type: 'blob', bookType: 'xlsx' });
    const fileName = 'BOM_' + comp.code + '_V' + comp.version + '.xlsx';
    await writeFile(subDir, fileName, bomBlob);
  }

  UI.toast('导出完成，共 ' + components.length + ' 个部件', 'success');
}
```

### 4.6 文件夹导入流程（详细）

```javascript
// 以图文档导入为例
async importDocuments(onPreview, onConfirm) {
  // 1. 用户选择文件夹
  const dirHandle = await window.showDirectoryPicker({ mode: 'read' });

  // 2. 查找图文档清单.xlsx
  let listFileHandle = null;
  for await (const entry of dirHandle.values()) {
    if (entry.name === '图文档清单.xlsx') listFileHandle = entry;
  }
  if (!listFileHandle) { UI.toast('未找到图文档清单.xlsx', 'error'); return; }

  // 3. 读取并解析 Excel
  const listFile = await listFileHandle.getFile();
  const data = await parseExcel(listFile);

  // 4. 扫描 attachments/ 子文件夹
  const attDir = await dirHandle.getDirectoryHandle('attachments').catch(() => null);
  const attachments = [];
  if (attDir) {
    for await (const entry of attDir.values()) {
      const file = await entry.getFile();
      attachments.push({ name: entry.name, file: file });
    }
  }

  // 5. 预览 + 确认
  onPreview(data, attachments);

  // 6. 用户确认后执行导入
  onConfirm(data, attachments);
}
```

## 八、注意事项

1. **导入不删除**：导入只做新增和更新，不会删除已有数据
2. **冲突处理**：按 件号+版本 匹配，匹配到则更新（覆盖），未匹配则新增
3. **附件大小**：导入附件时单文件超过 1GB 给出警告
4. **导入上限**：单次导入上限 500 条主记录
5. **编码**：Excel 使用 UTF-8，文件名避免特殊字符
6. **断点续传**：大文件附件使用现有分块上传机制
7. **后端零改动**：所有导入导出在前端完成，通过现有 API 操作
8. **浏览器要求**：文件夹读写需要 Chrome 86+ 或 Edge 86+，其他浏览器退回 ZIP 方式
9. **文件夹命名约定**：导出文件夹名带日期（如 `部件数据_20260505`），方便按时间归档
