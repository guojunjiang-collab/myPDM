# PDM系统 核心数据导入导出功能设计方案

## 一、需求总览

实现零件、部件、图文档三大核心数据的完整导入导出，支持定期数据备份和迁移恢复。

### 导出需求

| 数据    | 导出内容                     | 格式                    |
| ----- | ------------------------ | --------------------- |
| 零件    | 全部字段 + 关联图文档列表           | 单个 Excel 文件           |
| 部件列表  | 全部部件（不含子项）               | Excel 文件              |
| 部件BOM | 每个部件的完整BOM树（多级子项）+ 关联图文档 | 文件夹：清单 + 每个部件一个 Excel |
| 图文档   | 全部字段 + 附件文件（含实体文件）       | 文件夹：清单 + 附件子文件夹       |

### 导入需求

| 数据  | 导入内容                        | 说明                  |
| --- | --------------------------- | ------------------- |
| 零件  | 全部字段 + 自定义字段 + 关联图文档        | 按件号+版本匹配，有则更新，无则新增  |
| 部件  | 多个顶层部件 + BOM子项（逐层导入）+ 关联图文档 | 选择导出的文件夹，反向还原       |
| 图文档 | 全部字段 + 附件文件（含实体文件）          | 选择导出的文件夹，元数据+附件一起导入 |

## 二、导出详细设计

### 2.1 零件导出

**触发**：零件管理页面顶部「📥 导出全部」按钮

**输出**：单个文件 `零件清单_YYYYMMDD.xlsx`，包含以下 Sheet：

| Sheet名 | 内容       | 列                                        |
| ------ | -------- | ---------------------------------------- |
| 零件数据   | 所有零件     | 件号、中文名称、规格型号、版本、状态、备注、创建时间、更新时间、自定义字段... |
| 关联图文档  | 零件-图文档关系 | 件号、零件版本、图文档编号、图文档名称、版本、状态                |

> 零件件号本身含版本唯一约束，不会重名，无需在文件名中加版本。

**下载方式**：浏览器直接下载（与现有方式相同）

## 三、导入详细设计

### 3.1 零件导入

**触发**：零件管理页面顶部「📤 导入」按钮

**输入**：单个 Excel 文件（与导出的 `零件清单.xlsx` 格式一致）

**流程**：

```
上传 Excel → 解析 Sheet"零件数据"
  ├── 校验必填字段（件号、名称）
  ├── 按 件号+版本 匹配本地数据
  │     ├── 匹配到 → 标记为"更新"
  │     └── 未匹配 → 标记为"新增"
  ├── 解析自定义字段列（按列名匹配字段定义）
  ├── 解析 Sheet"关联图文档"
  │     └── 关联关系待零件创建/更新后再处理
  └── 显示预览（含状态标记：新增/更新/错误 + 关联图文档警告数）
      └── 用户确认 → 批量创建/更新零件（含自定义字段）→ 建立关联图文档关系
```

**关联图文档处理**：

- Excel 中填的是图文档编号+版本
- 系统按编号+版本查找已有图文档
- 找不到的标记为"未找到"警告，跳过该关联

**自定义字段处理**：

- 导入时从 Excel 列名匹配自定义字段定义的 `name`
- 匹配到的字段值写入 `customFields` 对象
- 未匹配的列忽略

**导入后自动刷新**：导入完成后调用 `Store.onLogin().then()` 刷新数据再重新渲染页面。

### 3.2 部件导入

**触发**：部件管理页面顶部「📤 导入」按钮

**输入**：用户选择一个文件夹（与导出结构一致）

**流程**：

```
用户选择文件夹 → 扫描目录结构
  ├── 查找"部件清单.xlsx" → 解析部件列表
  │     ├── 校验必填字段
  │     ├── 按 件号+版本 匹配 → 标记新增/更新
  │     └── 解析"关联图文档"Sheet → 收集关联数据
  ├── 查找所有"BOM_*.xlsx" → 解析每个部件的BOM树
  │     ├── 按文件名提取部件件号和版本
  │     │     格式：BOM_ASM-001_A.xlsx → 件号=ASM-001, 版本=A
  │     │     解析方式：从右往左用"_"拆分，最后一段为版本，前面为件号
  │     └── 匹配到对应部件后附加 bomRows 数据
  └── 显示预览（含BOM匹配数和关联图文档数量）
      └── 用户确认 → 执行导入
```

**执行导入（三轮处理）**：

**第一轮：创建/更新所有部件**

- 按 件号+版本 匹配已有部件
- 匹配到 → PUT 更新（含自定义字段）
- 未匹配 → POST 新增，记录 `_newId`

**第二轮：建立 BOM 子项关系**

- 按层级排序，**只处理层级=1的直接子项**（层级>1的由其父部件的BOM文件负责）
- 子项查找优先级：
  1. 先在 preview 数组中查找（本轮新建的部件）
  2. 再在 Store 中查找已有零件/部件
  3. 零件找不到时自动创建（草稿状态，仅填写 BOM 中的信息）
- 已存在的子项关系跳过（不重复添加）
- 使用 `API.addAssemblyPart()` 调用后端接口（与 Store 一致）
- 请求体：`{ child_type: 'part'/'component', child_id: UUID, quantity: Number }`

**多层级 BOM 导入原理**：

```
ASM-001 的 BOM 文件：
  层级0: ASM-001（自身，跳过）
  层级1: ASM-002（直接子项）→ 导入到 ASM-001 ✅
  层级1: PRT-001（直接子项）→ 导入到 ASM-001 ✅
  层级2: PRT-002（ASM-002的子项）→ ❌ 不导入到 ASM-001

ASM-002 的 BOM 文件：
  层级0: ASM-002（自身，跳过）
  层级1: PRT-002（直接子项）→ 导入到 ASM-002 ✅
```

> 每个部件只导入自己的直接子项（层级1），深层子项由各自子部件的 BOM 文件负责，确保不重复。

**第三轮：建立关联图文档关系**

- 从部件清单的「关联图文档」Sheet 中读取关联数据
- 按 部件件号+版本 匹配部件 ID
- 按 图文档编号+版本 在 Store 中查找图文档
- 调用 `POST /assemblies/{id}/documents` 建立关联

**导入后自动刷新**：导入完成后调用 `Store.onLogin().then()` 刷新数据再重新渲染页面。

### 3.3 图文档导入

**输入**：用户选择一个文件夹（与导出结构一致）

**流程**：

```
用户选择文件夹 → 扫描目录结构
  ├── 查找"图文档清单.xlsx" → 解析图文档列表
  │     ├── 校验必填字段（编号、名称）
  │     ├── 按 编号+版本 匹配 → 标记新增/更新
  │     └── 显示预览
  ├── 扫描 attachments/ 子文件夹中的文件
  │     └── 按文件名前缀（编号_版本）匹配图文档记录
  └── 用户确认 → 批量创建/更新图文档 → 上传附件文件
```

**附件上传处理**：

- 前端逐个读取附件文件
- 通过现有分块上传 API 上传到后端
- 关联到对应的图文档记录
- 单文件超过 1GB 给出警告

## 四、技术方案

### 4.1 浏览器文件夹操作

使用 **File System Access API** 实现文件夹读写：

| API                         | 用途            | 浏览器支持                |
| --------------------------- | ------------- | -------------------- |
| `showDirectoryPicker()`     | 导出时让用户选择保存文件夹 | Chrome 86+, Edge 86+ |
| `showOpenFilePicker()`      | 导入时让用户选择文件夹   | Chrome 86+, Edge 86+ |
| `FileSystemDirectoryHandle` | 读写文件夹中的文件     | 同上                   |

> **仅支持 Chrome 86+ / Edge 86+**，不支持时提示用户更换浏览器。

### 4.2 关键 API 接口

**BOM 子项操作**：

- `API.addAssemblyPart(assemblyId, { child_type, child_id, quantity })` — 添加子项
- `GET /assemblies/{id}/parts` — 获取子项列表（用于查重）
- `DELETE /assemblies/{asmId}/parts/{itemId}` — 删除子项

**关联图文档操作**：

- `POST /parts/{id}/documents` — 零件关联图文档
- `POST /assemblies/{id}/documents` — 部件关联图文档

## 七、注意事项

1. **导入不删除**：导入只做新增和更新，不会删除已有数据
2. **冲突处理**：按 件号+版本 匹配，匹配到则更新（覆盖），未匹配则新增
3. **附件大小**：导入附件时单文件超过 1GB 给出警告
4. **编码**：Excel 使用 UTF-8，文件名避免特殊字符
5. **断点续传**：大文件附件使用现有分块上传机制
6. **后端零改动**：所有导入导出在前端完成，通过现有 API 操作
7. **浏览器要求**：文件夹读写需要 Chrome 86+ 或 Edge 86+，不支持时提示用户更换浏览器
8. **文件夹命名约定**：导出文件夹名带日期（如 `部件数据_20260505`），方便按时间归档
9. **BOM 导入只处理层级1**：每个部件只导入直接子项（层级=1），深层子项由子部件自己的 BOM 文件负责，避免多层级重复
10. **BOM 子项自动创建零件**：导入时遇到系统中不存在的零件，自动创建草稿状态的零件记录
11. **BOM 子项去重**：添加子项前先检查已有关系，已存在则跳过
