## 1. 功能概述

### 1.1 什么是构型项

构型项是构型配置体系的基础单元，描述了一个产品单元的组成方式。例如"某机型机翼构型"包含了哪些零件、哪些是可选的替代件、与哪些子构型构成层级关系。

一个构型项定义了该产品单元的**所有可能**组成（必选件 + 可选件 + 子构型项），供构型配置模块据此展开配置清单。

### 1.2 核心能力

- **定义构型项**：创建可独立管理的配置单元（如"A型机翼"），录入构型号、名称、规格、备注
- **绑定零部件**：指定构型由哪些零件/部件组成，并标注每种零件是必选还是可选
- **构型嵌套**：支持构型项之间的层级引用，子构型可被父构型包含
- **关联图文档**：构型项可直接关联图文档（图纸、技术规范等），复用零部件图文档关联的交互模式
- **循环引用防护**：不允许将自身设为子项，新建子构型时自动排除所有祖先节点

### 1.3 使用场景

| 场景       | 描述 |
|-----------|------|
| 基础构型定义 | 定义"标准型机翼"包含襟翼、副翼、缝翼等固定部件 |
| 可选方案管理 | 导航灯提供 A/B 两种型号，用户可以按需选择 |
| 构型嵌套   | "整机构型"包含"机翼构型""机身构型"等多个子构型 |
| 图文档关联 | 构型项关联设计图纸、技术规范等图文档，方便查阅 |

### 1.4 模块关系

```
构型项管理                          构型配置
（定义"有什么"）                    （决定"用哪个"）
     │                                  │
     │  构型项 + 子构型项层级             │  选择构型项
     │  必选/可选零部件                   │  展开配置清单
     │  关联图文档                       │  架次有效性
     │                                  │
     └────────── 引用 ──────────────────┘
```

## 2. 数据模型

### 2.1 数据表

#### `configuration_items` — 构型项主表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | UUID | PK | 主键 |
| `code` | VARCHAR(64) | UNIQUE NOT NULL | 构型号（唯一编码） |
| `name` | VARCHAR(255) | NOT NULL | 名称 |
| `spec` | VARCHAR(255) | | 规格型号 |
| `remark` | TEXT | | 备注 |
| `document_links` | JSONB | DEFAULT '[]' | 关联图文档列表 `[{id, document_id, category, sort_order}]` |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | |
| `updated_at` | TIMESTAMPTZ | DEFAULT NOW() | |

#### `configuration_item_parts` — 关联零部件表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | UUID | PK | |
| `configuration_item_id` | UUID | FK→configuration_items, CASCADE | 所属构型项 |
| `part_type` | VARCHAR(16) | NOT NULL | 'part' / 'assembly' |
| `part_id` | UUID | NOT NULL | 零部件 ID |
| `is_required` | BOOLEAN | NOT NULL, DEFAULT TRUE | 必选/可选 |
| `sort_order` | INTEGER | DEFAULT 0 | 排序 |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | |

#### `configuration_item_children` — 子构型项表

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | UUID | PK | |
| `parent_id` | UUID | FK→configuration_items, CASCADE | 父构型项 |
| `child_id` | UUID | FK→configuration_items, CASCADE | 子构型项 |
| `is_required` | BOOLEAN | NOT NULL, DEFAULT TRUE | 必选/可选 |
| `sort_order` | INTEGER | DEFAULT 0 | 排序 |
| `created_at` | TIMESTAMPTZ | DEFAULT NOW() | |

> `(parent_id, child_id)` 有唯一约束 `uix_config_child`，防止重复添加。

### 2.2 结构示意

```
整机构型 (CFG-AIRCRAFT)
├── 关联零部件:
│   ├── 起落架 (必选)
│   └── 航电系统 (必选)
├── 关联图文档:
│   ├── A型总装图 (DRW-001)
│   └── 技术规范 (DOC-002)
└── 子构型: 机翼构型 (必选)
    ├── 关联零部件:
    │   ├── 襟翼 (必选)
    │   └── 副翼 (必选)
    ├── 关联图文档:
    │   └── 机翼装配图 (DRW-010)
    └── 子构型: 襟翼构型 (可选)
```

### 2.3 设计要点

| 要点 | 说明 |
|------|------|
| 关联关系只记引用 | 不复制零件/部件数据，保证数据一致性 |
| 不记版本 | 构型项修改即生效，不保留历史版本 |
| 不记状态 | 构型项无生命周期（草稿/发布等），降低操作复杂度 |
| 不记数量 | 零部件和子构型只关注"是否关联"，不关注用量 |
| 循环引用防护 | 新建/编辑子构型时，通过 BFS 向上查找所有祖先节点并排除 |
| 图文档关联复用 | 与零件/部件共用 `EntityDocumentSection` 组件和 `DocumentPicker` 弹窗，数据存储格式完全一致 |

## 3. API 设计

### 3.1 端点总览

| 方法 | 端点 | 说明 | 权限 |
|------|------|------|------|
| `GET` | `/configurations/items` | 列表（分页、搜索，支持排除祖先节点） | 全部 |
| `GET` | `/configurations/items/{id}` | 详情 + 关联零部件 + 子构型项 + 图文档 | 全部 |
| `POST` | `/configurations/items` | 新建构型项 | admin, engineer |
| `PUT` | `/configurations/items/{id}` | 编辑构型项基本信息 | admin, engineer |
| `DELETE` | `/configurations/items/{id}` | 删除构型项及关联数据 | admin, engineer |
| `POST` | `/configurations/items/{id}/parts` | 批量添加关联零部件 | admin, engineer |
| `PUT` | `/configurations/items/{id}/parts/{part_id}` | 修改关联零件（必选/可选/排序） | admin, engineer |
| `DELETE` | `/configurations/items/{id}/parts/{part_id}` | 移除关联零部件 | admin, engineer |
| `POST` | `/configurations/items/{id}/children` | 批量添加子构型项 | admin, engineer |
| `PUT` | `/configurations/items/{id}/children/{child_id}` | 修改子构型（必选/可选/排序） | admin, engineer |
| `DELETE` | `/configurations/items/{id}/children/{child_id}` | 移除子构型项关联 | admin, engineer |
| `GET` | `/configurations/items/{id}/documents` | 获取关联图文档列表 | 全部 |
| `POST` | `/configurations/items/{id}/documents` | 关联图文档 | admin, engineer |
| `PUT` | `/configurations/items/{id}/documents/{link_id}` | 更新图文档关联信息（类别/排序） | admin, engineer |
| `DELETE` | `/configurations/items/{id}/documents/{link_id}` | 移除图文档关联 | admin, engineer |

### 3.2 列表查询参数

| 参数 | 类型 | 说明 |
|------|------|------|
| `page` | int | 页码（默认 1） |
| `page_size` | int | 每页条数（默认 20，最大 100） |
| `search` | string | 按构型号/名称/规格模糊搜索 |
| `exclude_ancestors_of` | UUID | 排除指定构型项的所有祖先（防止循环引用） |

## 4. 前端设计

### 4.1 页面结构

```
Configuration.tsx
├── 构型项管理 Tab → ConfigurationList
│   ├── 搜索框 + 新建按钮（仅 admin/engineer 可见）
│   ├── 列表表格（构型号/名称/规格/备注/创建时间）
│   │   └── 行点击 → ConfigurationDetailModal
│   └── 行操作按钮（编辑/删除，按权限显示）
│
│   ConfigurationCreateModal（新建/编辑构型项）
│   ├── 基本信息表单（构型号/名称/规格/备注）
│   ├── 关联零部件区域
│   │   ├── 零件选择器（PartPicker）→ 从零件库/部件库选择
│   │   └── 已选列表（件号/名称/类型/必选开关/删除按钮）
│   ├── 子构型项区域
│   │   ├── 构型项选择器 → 从构型库选择（自动排除自身和祖先）
│   │   └── 已选列表（构型号/名称/必选开关/删除按钮）
│   └── 关联图文档区域 → EntityDocumentSection（复用）
│
│   ConfigurationDetailModal（查看构型项详情）
│   ├── 基本信息（构型号/名称/规格/备注）
│   ├── 关联零部件列表（件号/名称/类型/必选/可选）
│   ├── 子构型项列表（构型号/名称/必选/可选）
│   └── 关联图文档列表 → EntityDocumentSection（复用）
│
└── 构型配置 Tab → ProfileList / ProfileEditModal
```

### 4.2 列表页

- 按构型号/名称搜索，分页浏览
- 点击行查看详情（`ConfigurationDetailModal`）
- 管理员/工程师可新建、编辑；工程师不可删除
- 排序图标使用 `cursor-pointer select-none whitespace-nowrap`

### 4.3 新建/编辑弹窗

- 模态窗口，表单包含：构型号、名称、规格、备注
- 关联零部件：通过零件/部件选择器添加，支持标记必选/可选
- 子构型项：通过构型项选择器添加，自动排除自身及祖先（防止循环引用）
- 图文档：复用 `EntityDocumentSection` 组件，交互模式与零件/部件完全一致

### 4.4 详情弹窗

- 点击列表行弹出，展示完整信息
- 包含基本信息、关联零部件、子构型项、关联图文档
- 图文档区域支持附件预览和下载
- 仅有查看功能，不可编辑

### 6.4 循环引用防护

```python
# BFS 向上查找所有祖先，新建/编辑子构型时排除
exclude_ids = set()
queue = [target_config_id]
while queue:
    cid = queue.pop(0)
    parents = child_to_parents.get(cid, [])
    for pid in parents:
        if pid not in exclude_ids:
            exclude_ids.add(pid)
            queue.append(pid)
```

## 7. 设计决策

| 决策 | 理由 |
|------|------|
| 不记版本 | 构型项修改即生效，不保留历史版本，保持简洁 |
| 不记状态 | 构型项无生命周期（草稿/发布等），降低操作复杂度 |
| 不记数量 | 零部件和子构型只关注"是否关联"，不关注用量 |
| 点击行即详情 | 减少操作步骤，点一下就能看到完整信息 |
| 图文档关联复用 | 与零件/部件共用 `EntityDocumentSection` 组件和 `DocumentPicker` 弹窗，保持交互一致性 |
| JSONB 存储图文档关联 | `document_links` 字段格式与零件/部件完全一致 `[{id, document_id, category, sort_order}]` |
| 批量添加零部件/子构型 | 通过 `BulkCreate` schema 一次请求添加多个，减少网络往返 |
| 循环引用防护 | BFS 向上遍历所有祖先节点并排除，防止配置展开时死循环 |
