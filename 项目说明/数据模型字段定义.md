## 1. 零部件（Component）

**表名：`components`**

零件（Part）和部件/总成（Assembly）已统一合并为零部件（Component），通过运行时逻辑区分类型：在 BOM 中作为父项出现的为 `assembly`，否则为 `part`。数据库表 `components` 中不存储区分列，`type` 由 API 响应时动态计算。

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK, DEFAULT uuid_generate_v4() | 主键 |
| `code` | VARCHAR(64) | NOT NULL | 零部件编码（唯一，配合 version 联合唯一） |
| `name` | VARCHAR(255) | NOT NULL | 零部件名称 |
| `spec` | VARCHAR(255) | 可空 | 规格型号 |
| `version` | VARCHAR(32) | DEFAULT 'A' | 版本号 |
| `status` | VARCHAR(32) | NOT NULL, DEFAULT 'draft' | 状态：draft / frozen / released / obsolete |
| `remark` | TEXT | 可空 | 备注 |
| `revisions` | JSONB | DEFAULT '[]' | 版本变更记录数组 |
| `revision_parent_id` | UUID | 可空 | 升版来源版本 ID（非升版创建时为 NULL） |
| `creator_id` | UUID | 可空 | 创建者 ID |
| `document_links` | JSONB | DEFAULT '[]' | 关联图文档列表，格式：`[{id, document_id, category, sort_order, created_at}]` |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | 创建时间 |
| `updated_at` | TIMESTAMPTZ | DEFAULT now(), 自动更新 | 更新时间 |
| `deleted_at` | TIMESTAMPTZ | 可空, DEFAULT NULL | 软删除时间 |

**索引：** 唯一索引 `uix_component_code_version ON components (code, version) WHERE deleted_at IS NULL`

**类型区分规则（非数据库字段，由 API 运行时判断）：**
- `type = "assembly"`：该零部件在 `bom_items` 中作为父项出现（`parent_type = 'component'` 且 `parent_id = 该 id`）
- `type = "part"`：不在 BOM 中担任父项

## 3. BOM 关系（BOMItem）

**表名：`bom_items`**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK | 主键 |

## 4. 用户看板

### 4.1 看板主表（UserDashboard）

**表名：`user_dashboards`**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK, DEFAULT uuid_generate_v4() | 主键 |
| `user_id` | UUID | FK → users(id), UNIQUE, ON DELETE CASCADE | 所属用户（每用户一个） |
| `name` | VARCHAR(128) | DEFAULT '我的看板' | 看板名称 |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | 创建时间 |
| `updated_at` | TIMESTAMPTZ | DEFAULT now(), 自动更新 | 更新时间 |

### 4.2 文件夹（DashboardFolder）

**表名：`dashboard_folders`**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK, DEFAULT uuid_generate_v4() | 主键 |
| `dashboard_id` | UUID | FK → user_dashboards(id), ON DELETE CASCADE | 所属看板 |
| `parent_id` | UUID | FK → dashboard_folders(id), ON DELETE CASCADE, 可空 | 父文件夹（NULL = 根级） |
| `name` | VARCHAR(128) | NOT NULL | 文件夹名称 |
| `sort_order` | INTEGER | DEFAULT 0 | 排序序号 |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

**树形结构：** 通过 `parent_id` 自引用实现无限层级。

### 4.3 文件夹关联项（DashboardItem）

**表名：`dashboard_items`**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK, DEFAULT uuid_generate_v4() | 主键 |
| `folder_id` | UUID | FK → dashboard_folders(id), ON DELETE CASCADE | 所属文件夹 |
| `entity_type` | VARCHAR(16) | NOT NULL | 实体类型：`"component"` / `"document"` |
| `entity_id` | UUID | NOT NULL | 实体 ID |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

**联合唯一约束：** `(folder_id, entity_type, entity_id)` — 同一文件夹内同一实体不能重复添加。

> **注意：** 统一迁移后 `entity_type` 的值已统一为 `"component"`（替代原有的 `"part"` / `"assembly"`）。

### 4.4 文件夹共享（DashboardFolderShare）

**表名：`dashboard_folder_shares`**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK, DEFAULT uuid_generate_v4() | 主键 |
| `folder_id` | UUID | FK → dashboard_folders(id), ON DELETE CASCADE | 被共享的文件夹 |
| `shared_with_user_id` | UUID | FK → users(id), ON DELETE CASCADE | 被共享给的用户 |
| `permission` | VARCHAR(16) | NOT NULL, DEFAULT `'view'` | 权限：`"view"` / `"edit"` |
| `created_at` | TIMESTAMPTZ | DEFAULT now() | 创建时间 |

**联合唯一约束：** `(folder_id, shared_with_user_id)` — 同一文件夹对同一用户只能有一条共享记录。

## 6. 自定义字段

### 6.1 字段定义（CustomFieldDefinition）

**表名：`custom_field_definitions`**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK, DEFAULT uuid_generate_v4() | 主键 |
| `name` | VARCHAR(128) | NOT NULL | 显示名称 |

### 6.2 字段值（CustomFieldValue）

**表名：`custom_field_values`**

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | UUID | PK, DEFAULT uuid_generate_v4() | 主键 |
| `field_id` | UUID | FK → custom_field_definitions(id), ON DELETE CASCADE | 字段定义 |

| `value_text` | TEXT | 可空 | 文本/单选值 |
| `value_number` | DECIMAL(12,4) | 可空 | 数字值 |
| `value_json` | JSONB | 可空 | 多选值数组 |

| `updated_at` | TIMESTAMPTZ | DEFAULT now(), 自动更新 | 更新时间 |

**存储规则：**
- `text` / `select` 类型 → 存入 `value_text`
- `number` 类型 → 存入 `value_number`

## 9. ER 关系概览

```
users ──1:1── user_dashboards
                  │
                  ├──1:N── dashboard_folders (树形自引用 parent_id)
                  │           │
                  │           ├──1:N── dashboard_items (→ components / documents)
                  │           │
                  │           └──1:N── dashboard_folder_shares (→ users)
                  │
components ──1:N── bom_items (自引用：父项 → 子项)
  │                    │
  │         (parent_type='component' / child_type='component')
  │
  ├── document_links (JSONB → documents)
  ├── component_attachments (CAD / 生产附件，文件系统存储)
  └── custom_field_values

documents ──1:N── document_attachments (文件系统存储)
  │
  └── document_group_links ──N:1── user_groups

custom_field_definitions ──1:N── custom_field_values

user_groups ──N:M── users (via user_group_members)
              N:M── documents (via document_group_links)
```

## 12. 统一迁移说明

### 背景
零件（`parts`）和部件/总成（`assemblies`）两张表结构和功能高度相似，v1.6.x 版本将其统一合并为 `components` 表。

### 迁移方式
迁移在系统启动时自动执行（`migrations_components.py` / `initdb/migrations/007_components_unification.sql`）：
1. 创建 `components` 表和 `component_attachments` 表（幂等：IF NOT EXISTS）
2. 将 `parts` 数据插入 `components` 表
3. 将 `assemblies` 数据插入 `components` 表
4. 更新引用表的外键类型值：
   - `bom_items.parent_type` / `child_type` → `"component"`
   - `custom_field_values.entity_type` → `"component"`
   - `custom_field_definitions.applies_to` 数组内替换 → `"component"`
   - `dashboard_items.entity_type` → `"component"`
   - `ecr_affected_items.entity_type` → `"component"`
   - `eco_execution_items.entity_type` → `"component"`
   - `inventory_materials.ref_entity_type` → `"component"`
   - `project_task_links.entity_type` → `"component"`
5. 数据完整性校验通过后删除旧表 `parts` / `assemblies`
6. `operation_logs.target_type` 保留历史值，前端展示时统一映射

### 运行时类型区分
数据库 `components` 表中**不存储** `component_type` 列。类型（`part` / `assembly`）由 API 响应时动态计算：
- 在 `bom_items` 中作为父项出现 → `assembly`
- 否则 → `part`

此设计避免数据冗余，且同一零部件可根据 BOM 配置在不同上下文中扮演不同角色。
