# 飞书免登配置指南

## 一、方案概述

myPDM 支持两套独立的飞书身份体系，互不干扰：

| Provider | 对应飞书应用 | 说明 |
| --- | --- | --- |
| `feishu` | 普通飞书应用（本文示例称 A） | 主租户用户 |
| `feishu_eh` | EH 飞书应用（本文示例称 B） | EH 租户用户 |

认证方式为**浏览器 OAuth 授权码流程**（`authen/v1/authorize` → 回调换 token → 取用户信息 → 自动建号/登录），**不依赖 JSAPI `requestAccess`**，因此：

- 不需要在飞书后台配置「H5 可信域名」；
- 飞书客户端内通过 UA 检测自动发起 OAuth 跳转，体验同样是免登；
- 回调地址两个 provider 共用同一个：`{FEISHU_REDIRECT_BASE}/api/auth/feishu/callback`，由后端通过 state 区分是哪个应用。

首次登录飞书用户会自动创建系统账号（默认 `guest` 角色），之后同一 union_id 直接登录。

## 二、后端配置（.env）

所有凭据和回调基址都在仓库根目录 `.env` 中配置，**该文件已被 .gitignore 忽略，不会入库**：

```env
# 普通飞书应用
FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# EH 飞书应用（不配则不显示「飞书登录（EH）」按钮）
FEISHU_EH_APP_ID=cli_xxxxxxxxxxxxxxxx
FEISHU_EH_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# 回调基址：所有 provider 的回调都会拼成 {FEISHU_REDIRECT_BASE}/api/auth/feishu/callback
FEISHU_REDIRECT_BASE=http://192.168.61.105:8081
```

要点：

- `FEISHU_REDIRECT_BASE` 建议使用 http 入口（如 `http://192.168.61.105:8081`），与飞书后台配置保持一致；结尾不要带斜杠。
- 修改 `.env` 后需重建后端容器才会生效：

  ```powershell
  docker compose up -d --force-recreate backend
  ```

- 验证配置是否下发：

  ```powershell
  curl http://192.168.61.105:8081/api/auth/feishu/config
  ```

  返回的 `providers` 列表中应包含已配置的应用（app_id 为各应用的 App ID）。

## 三、飞书开放平台后台配置

普通飞书（A）和 EH 飞书（B）**各自**按以下步骤配置，互不共用：

1. **创建企业自建应用**
   在飞书开放平台创建「企业自建应用」，能力选择「网页应用」（不需要机器人/小程序能力）。

2. **记录凭证**
   「凭证与基础信息」页面查看 App ID（`cli_xxx`）和 App Secret，填入 `.env` 对应变量。

3. **安全设置 → 重定向 URL**
   添加（注意不要带结尾斜杠）：

   ```
   http://192.168.61.105:8081/api/auth/feishu/callback
   ```

   这条必须与 `.env` 中 `FEISHU_REDIRECT_BASE` 拼出的地址完全一致。

4. **权限管理 → API 权限**
   开通「获取用户基本信息」（`contact:user.base:readonly`），免登自动建号需要读取姓名等信息。

5. **应用发布 → 版本管理与发布**
   创建版本，填写版本号和说明，确认可用范围包含测试用户，提交并发布。**后台任何配置修改都必须重新发布版本才生效。**

6. **（可选）工作台主页**
   如果希望用户在飞书工作台点击应用图标直接进入系统：

   - 普通飞书应用（A）主页：
     ```
     http://192.168.61.105:8081/login
     ```
   - EH 飞书应用（B）主页：
     ```
     http://192.168.61.105:8081/login?feishu_provider=feishu_eh
     ```

   > 带 `?feishu_provider=feishu_eh` 是为了让客户端内自动免登走 EH 应用；否则默认走普通飞书（A），EH 用户会报「没有 A 应用权限」。

7. **不需要配置**：H5 可信域名、JSAPI 鉴权签名等（当前方案不使用 JSAPI）。

## 四、前端行为说明

- 登录页按钮由 `GET /api/auth/feishu/config` 动态下发：配了哪个 provider，页面就显示哪个按钮。
- 飞书客户端内打开登录页会自动发起 OAuth 免登：
  - 默认选择普通飞书（`feishu`）；
  - URL 带 `?feishu_provider=feishu_eh` 时选择 EH（`feishu_eh`）。
- OAuth 回调由 `/feishu-callback` 页面接收令牌并完成登录；失败会带 `error` 回到登录页展示，不会循环跳转。

## 五、常见问题排查

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 提示「没有 XX 应用权限」 | 用户不在该应用的可用范围/租户不匹配，或入口 provider 选错（EH 用户走了默认 A 入口） | 核对应用可用范围；EH 用户使用带 `?feishu_provider=feishu_eh` 的入口 |
| 授权页报 `redirect_uri` 不合法（20029） | 后台重定向 URL 未配置、未发布，或与 `.env` 的 `FEISHU_REDIRECT_BASE` 不一致 | 核对后台重定向 URL 与回调地址完全一致，重新发布版本 |
| 报「应用未发布 / 无应用权限」 | 版本未发布，或可用范围未包含当前用户 | 发布新版本，检查可用范围 |
| 配置改了但行为没变 | 飞书后台配置修改后未重新发布 | 创建版本并发布 |
| 客户端内出现「授权被终止」（2700002） | 历史 JSAPI 方案遗留问题 | 当前版本已改为纯 OAuth，无需处理；如未来启用 JSAPI，需再配置 H5 可信域名 |

## 六、注意事项

- **凭据安全**：App Secret 只放 `.env`，不要提交到代码库，不要写入日志。
- **地址一致性**：`.env` 的 `FEISHU_REDIRECT_BASE` 与飞书后台重定向 URL 必须完全一致（协议、IP/域名、端口、路径）。
- **IP 变更**：当前配置使用局域网 IP `192.168.61.105`，机器 IP 变化后需同步修改 `.env` 和飞书后台的重定向 URL（及可选主页），并重新发布版本。
- **HTTP/HTTPS**：飞书客户端环境建议使用 http 入口（`http://192.168.61.105:8081`，nginx 已同时提供）；普通浏览器访问 `https://192.168.61.105:8080` 不受影响。
- **自动建号**：飞书用户首次登录自动创建 `guest` 账号，如需调整角色到「用户管理」中修改。

## 七、相关代码位置

- 后端：`backend/app/routers/feishu.py`（config/authorize/callback/jsapi 路由）、`backend/app/feishu_client.py`（双 provider 与 OpenAPI 调用）
- 前端：`frontend/src/pages/Login.tsx`（按钮与客户端自动免登）、`frontend/src/pages/FeishuCallback.tsx`（回调页）、`frontend/src/lib/feishu.ts`（飞书 UA 检测与 JSAPI 工具，当前未使用 JSAPI 路径）
- 部署：`docker-compose.yml`（向 backend 注入 `FEISHU_*` 环境变量）、`nginx/nginx.conf`（http/https 双入口）
