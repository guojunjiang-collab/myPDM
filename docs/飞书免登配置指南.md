# 飞书免登配置指南

## 一、方案概述

myPDM 支持通过飞书 OAuth 一键登录。飞书入口采用**多 provider（多企业）**设计：系统可接入任意多个企业的飞书应用，每个企业一套 `AppID`/`AppSecret`，登录页与绑定面板按配置自动渲染。

- **单路（默认）**：不配置 `FEISHU_PROVIDERS` 时，仅启用主飞书入口 `feishu`。
- **多路（多企业）**：设置 `FEISHU_PROVIDERS=feishu,companyB,companyC` 后，自动启用对应多路入口，每个 key 对应一套环境变量。

| Provider key | 环境变量前缀 | 说明 |
| --- | --- | --- |
| `feishu` | `FEISHU_` | 主飞书入口（默认存在） |
| 任意其它 key（如 `companyB`） | `FEISHU_<KEY大写>_`（如 `FEISHU_COMPANYB_`） | 各企业/组织的飞书应用，名称中性、不含具体公司品牌 |

认证方式为**浏览器 OAuth 授权码流程**（`authen/v1/authorize` → 回调换 token → 取用户信息 → 自动建号/登录），**不依赖 JSAPI `requestAccess`**，因此：

- 不需要在飞书后台配置「H5 可信域名」；
- 飞书客户端内通过 UA 检测自动发起 OAuth 跳转，体验同样是免登；
- 所有 provider 共用同一个回调地址：`{FEISHU_REDIRECT_BASE}/api/auth/feishu/callback`，由后端通过 state 中的 `provider` 区分是哪个应用。

首次登录飞书用户会自动创建系统账号（默认 `unverified` 角色，需管理员审批），之后同一 `(provider, union_id)` 直接登录。不同企业的 `union_id` 命名空间天然隔离，互不冲突。

## 二、后端配置（.env）

所有凭据和回调基址都在仓库根目录 `.env` 中配置，**该文件已被 .gitignore 忽略，不会入库**：

```env
# 飞书多企业接入：逗号分隔 provider key，未设置时默认仅主入口 feishu（单路）
FEISHU_PROVIDERS=feishu,companyB

# 主飞书应用（前缀 FEISHU_）
FEISHU_APP_ID=cli_xxxxxxxxxxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# 第二路飞书应用（前缀 FEISHU_COMPANYB_，显示名可配）
FEISHU_COMPANYB_APP_ID=cli_xxxxxxxxxxxxxxxx
FEISHU_COMPANYB_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
FEISHU_COMPANYB_NAME=飞书登录（乙公司）

# 回调基址：所有 provider 的回调都会拼成 {FEISHU_REDIRECT_BASE}/api/auth/feishu/callback
FEISHU_REDIRECT_BASE=http://192.168.61.105:8081
```

环境变量规则：

- `FEISHU_PROVIDERS`：逗号分隔的 provider key 列表；**未设置时默认 `feishu`**。仅在 `.env` 中存在对应 `APP_ID`/`APP_SECRET` 的 provider 才会出现在登录页。
- 每个 provider key `X` 对应：`FEISHU_<X大写>_APP_ID`、`FEISHU_<X大写>_APP_SECRET`、`FEISHU_<X大写>_NAME`（可选显示名）、`FEISHU_<X大写>_REDIRECT_BASE`（可选，覆盖全局回调基址）。
- 显示名 `NAME`：未配置时，`feishu` → `飞书登录`，其它 → `飞书登录（{key}）`。

要点：

- `FEISHU_REDIRECT_BASE` 建议使用 http 入口（如 `http://192.168.61.105:8081`），与飞书后台配置保持一致；结尾不要带斜杠。
- 修改 `.env` 后需重建后端容器才会生效（docker-compose 后端已通过 `env_file: .env` 透传全部变量）：

  ```powershell
  docker compose up -d backend
  ```

- 验证配置是否下发：

  ```powershell
  curl http://192.168.61.105:8081/api/auth/feishu/config
  ```

  返回的 `providers` 列表中应包含已配置的应用（app_id 为各应用的 App ID，name 为显示名）。

## 三、飞书开放平台后台配置

`feishu` 与各企业飞书应用（`companyB` 等）**各自**按以下步骤配置，互不共用：

1. **创建企业自建应用**
    在飞书开放平台创建「企业自建应用」，能力选择「网页应用」（不需要机器人/小程序能力）。

2. **记录凭证**
    「凭证与基础信息」页面查看 App ID（`cli_xxx`）和 App Secret，填入 `.env` 对应变量（按 provider key 的前缀）。

3. **安全设置 → 重定向 URL**
    添加（注意不要带结尾斜杠）：

    ```
    http://192.168.61.105:8081/api/auth/feishu/callback
    ```

    这条必须与 `.env` 中 `FEISHU_REDIRECT_BASE` 拼出的地址完全一致。

4. **权限管理 → API 权限**
    开通「获取用户基本信息」（`contact:user.base:readonly`），免登自动建号需要读取姓名等信息。

5. **应用发布 → 版本管理与发布**
    创建版本，填写版本号和说明，确认可用范围包含测试用户，提交并发布。**后台任何配置修改都必须重新发布版本才生效。**

6. **（可选）工作台主页**
    如果希望用户在飞书工作台点击应用图标直接进入系统：

    - 主飞书应用（`feishu`）主页：
      ```
      http://192.168.61.105:8081/login
      ```
    - 其它飞书应用（如 `companyB`）主页，需带 `feishu_provider` 指定入口：
      ```
      http://192.168.61.105:8081/login?feishu_provider=companyB
      ```

    > 带 `?feishu_provider=<key>` 是为了让客户端内自动免登走对应应用；否则默认走主飞书（`feishu`），非该应用的用户会报「没有应用权限」。

7. **不需要配置**：H5 可信域名、JSAPI 鉴权签名等（当前方案不使用 JSAPI）。

## 四、前端行为说明

- 登录页按钮由 `GET /api/auth/feishu/config` 动态下发：配了哪些 provider，页面就显示哪些按钮。
- 飞书客户端内打开登录页会自动发起 OAuth 免登：
  - 默认选择主飞书（`feishu`）；
  - URL 带 `?feishu_provider=<key>` 时选择对应 provider（如 `companyB`）。
- OAuth 回调由 `/feishu-callback` 页面接收令牌并完成登录；失败会带 `error` 回到登录页展示，不会循环跳转。

## 五、已有账号绑定（自助绑定）

已有账号的用户登录系统后，可在「系统设置 → 飞书绑定」把任意飞书入口身份绑定到自己账号。绑定后该飞书入口免登直接进入原账号。

规则：

- 未绑定过的飞书身份 → 直接绑定到当前账号；
- 该飞书身份已误绑到 `guest`/`unverified` 账号 → 自动改绑到当前账号，原账号停用但保留数据；
- 该飞书身份已绑定其他正式账号 → 拒绝并提示，需由原账号在「飞书绑定」中先解绑；
- 每个飞书入口只能绑定一个账号，同一账号可分别绑定多个飞书入口；
- 支持解绑：在「飞书绑定」页面点击已绑定入口的「解除」即可。

## 六、常见问题排查

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 提示「没有 XX 应用权限」 | 用户不在该应用的可用范围/租户不匹配，或入口 provider 选错（B 企业用户走了默认 `feishu` 入口） | 核对应用可用范围；B 企业用户使用带 `?feishu_provider=companyB` 的入口 |
| 授权页报 `redirect_uri` 不合法（20029） | 后台重定向 URL 未配置、未发布，或与 `.env` 的 `FEISHU_REDIRECT_BASE` 不一致 | 核对后台重定向 URL 与回调地址完全一致，重新发布版本 |
| 报「应用未发布 / 无应用权限」 | 版本未发布，或可用范围未包含当前用户 | 发布新版本，检查可用范围 |
| 配置改了但行为没变 | 飞书后台配置修改后未重新发布，或 `.env` 改了未重建后端 | 创建版本并发布；`docker compose up -d backend` |
| 客户端内出现「授权被终止」（2700002） | 历史 JSAPI 方案遗留问题 | 当前版本已改为纯 OAuth，无需处理；如未来启用 JSAPI，需再配置 H5 可信域名 |

## 七、注意事项

- **凭据安全**：App Secret 只放 `.env`，不要提交到代码库，不要写入日志。
- **地址一致性**：`.env` 的 `FEISHU_REDIRECT_BASE` 与飞书后台重定向 URL 必须完全一致（协议、IP/域名、端口、路径）。
- **IP 变更**：当前配置使用局域网 IP `192.168.61.105`，机器 IP 变化后需同步修改 `.env` 和飞书后台的重定向 URL（及可选主页），并重新发布版本。
- **HTTP/HTTPS**：飞书客户端环境建议使用 http 入口（`http://192.168.61.105:8081`，nginx 已同时提供）；普通浏览器访问 `https://192.168.61.105:8080` 不受影响。
- **自动建号**：飞书用户首次登录自动创建 `unverified` 账号，需管理员在「用户管理 → 待审批」中分配角色后才可使用。

- 后端：`backend/app/routers/feishu.py`（config/authorize/callback 路由）、`backend/app/feishu_client.py`（`list_providers`/`provider_env_prefix` 多 provider 解析与 OpenAPI 调用）
- 前端：`frontend/src/pages/Login.tsx`（按钮与客户端自动免登）、`frontend/src/pages/FeishuCallback.tsx`（回调页）、`frontend/src/lib/feishu.ts`（飞书 UA 检测，当前未使用 JSAPI 路径）
- 部署：`docker-compose.yml`（后端通过 `env_file: .env` 透传 `FEISHU_*` 等全部变量）、`nginx/nginx.conf`（http/https 双入口）
