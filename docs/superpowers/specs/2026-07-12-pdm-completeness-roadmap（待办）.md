# myPDM 完成度评估与功能路线图

> 日期：2026-07-12
> 版本基线：v1.6.1
> 目的：通读现有实现，评估相对市面成熟 PDM 系统的完成度，梳理差距并给出分档路线图。

---

## 一、评估方法

本报告基于对后端 `backend/app/`（routers / crud / models / permissions / assistant / cad）与前端 `frontend/src/` 的实际代码通读，逐模块核实"已实现 / 部分实现 / 未实现"，并与市面成熟 PDM（PTC Windchill、Siemens Teamcenter、SOLIDWORKS PDM、Aras Innovator）的能力基线进行对比。

---

## 二、模块完成度总览

| 模块 | 完成度(10) | 核心结论 |
|------|:---:|------|
| 零部件管理（三层模型 Master/Revision/Iteration） | 9 | DocDoku 风格三层模型，扎实 |
| 签入签出（含级联签出/签入/撤销/强制签入） | 9 | 状态机完整，超出多数轻量 PDM |
| 版本管理（24 进制 A→ZZ，升版复制全数据） | 9 | 完整 |
| BOM 管理（树/对比/反查/导出/CAD 矩阵） | 8 | 算法扎实，缺高级 BOM 概念 |
| ECR/ECO 工程变更 | 8 | 全生命周期状态机 + 执行引擎，缺多级审批 |
| 配置管理（构型项/概要/工作清单） | 7 | 完整，缺配置 BOM 对比 |
| 项目管理（甘特图/CPM/依赖/自动排期） | 9 | 质量意外地高 |
| 库存管理（5 类单据过账引擎） | 8 | 完整，缺多单位换算 |
| 图文档 + 附件预览（PDF/Office/STP 3D/压缩包） | 9 | 企业级 |
| 权限体系（RBAC + 对象级策略，~140 项自动生成） | 8 | 缺字段级/状态级 |
| AI 助手（14 工具 + 技能系统） | 8 | 差异化亮点 |

**综合定位**：功能广度已覆盖商用 PDM 的约 70–80%。深度集中在"单实例内的完整闭环"，缺口主要集中在**企业级集成与协作能力**。

## 三、各模块实现明细

### 3.1 零部件 / 版本 / 签入签出（强项）

已实现：
- 三层数据模型 `PartMaster → PartRevision → PartIteration`（`models_parts.py`）
- 24 进制版本号 A→B→…→ZZ（不含 I/O），升版自动复制附件 + BOM + 自定义字段（`crud_parts.py`）
- 四态状态机 draft ↔ frozen ↔ released → obsolete
- 签入/签出/撤销签出/强制签入，且支持**沿 BOM 树的级联操作**
- 动态类型判定（有子项即 assembly，否则 part）
- 自定义字段、关联图文档、附件分块上传

### 3.2 BOM 管理（较强，有高级缺口）

已实现：
- BOM 树（扁平 + 递归嵌套 + 3D 展平世界矩阵）
- BOM 对比（递归展平后按件号路径匹配，增/删/改/无变化 + 数量忽略选项）
- BOM 反查 Where-Used（向上 10 层）+ 图文档反查
- BOM 导出 CSV、CAD 变换矩阵（`cad_instances` JSONB）、STEP 装配导入与子件拆分

未实现 / 部分：
- 替代料 / 可选件（BOM 行级）— ❌
- EBOM / MBOM 多视图 — ❌
- 参考位号 RefDes / BOM 行备注 / 计量单位 UOM — ❌
- BOM 行级有效性(Effectivity) — ❌（仅配置概要有生效区间字段）

### 3.3 ECR / ECO 工程变更（较强）

已实现：
- ECR：draft→reviewing→approved/rejected→closed，受影响对象、BOM 上/下溯源、知会人、状态日志、关联 ECO
- ECO：draft→reviewing→approved→executing→completed，4 种执行动作（create/upgrade/qty_change/delete）、实体克隆、级联升版、提交自动冻结 / 撤回精确解冻、一键发布全层级

未实现 / 部分：
- **多级顺序审批**（`reviewers[].seq` 字段已预留但未用于强制逐级流转）— ❌
- 审批超时 / 自动提醒 — ❌
- PDF 导出为前端生成，无后端端点 — ⚠️

### 3.4 配置管理（完整，缺对比）

已实现：构型项树形层级、零部件（必选/可选/数量）关联、配置概要状态机、工作清单自动生成、工作表↔正式清单双表机制、可选件勾选、强制重建、清单导入还原。

未实现：**两个配置概要之间的 BOM 配置差异对比** — ❌（无后端 `/compare` 端点）。

### 3.5 项目管理（强项）

已实现：项目/成员/任务层级树、任务类型（任务/里程碑/评审）、任务依赖（FS/SS/FF/SF + lag）、依赖环检测、**CPM 关键路径**、前向自动排期级联传播、日期汇总 rollup、甘特图、拖拽重排、任务评论、任务关联对象。

### 3.6 库存管理（完整）

已实现：仓库/物料/库存/流水、5 类单据（入库/出库/调拨/盘点/调整）过账引擎、审批流、安全库存预警、行锁并发安全、库管员门禁、从 PDM 启用物料。

未实现：多计量单位换算 — ❌。

### 3.7 图文档 + 附件（强项）

已实现：文档签入签出 + 迭代、生命周期状态、版本升级、引用反查、文档-用户组共享、PDF 内联预览（JWT 媒体令牌）、Office→PDF（LibreOffice）、STP→glTF 3D 预览（MayoConv）、压缩包浏览、分块上传/流式下载。

### 3.8 权限 / 用户 / 日志 / AI / 同步

- 权限：RBAC（admin/engineer/production/guest）+ 7 个对象级策略，~140 权限项，单一事实源自动生成。缺**字段级权限**与**声明式状态-权限绑定** — ❌
- 操作日志：覆盖增删改/签入签出/状态变更，但未覆盖登录登出/权限变更 — ⚠️
- AI 助手：SSE 流式、14 工具、4 技能、API 只读网关、附件正文提取。缺 RAG/向量检索、多模态、主动推送 — ❌
- 数据同步：仅前端轮询增量拉取；跨环境 push/pull 未实现 — ❌

## 四、与成熟 PDM 的差距 —— 分档路线图

### A 档 — 高价值、契合现有架构，建议优先

| # | 功能 | 现状 | 价值 | 预估成本 |
|---|------|------|------|:---:|
| A1 | **通知/消息中心**（站内信 + 待办 + 可选邮件） | cc_users 仅静态字段无推送 | 协作刚需，覆盖 ECR/ECO/签出/项目任务 | 中 |
| A2 | **多级顺序审批工作流** | 单级会签/或签，seq 已预留 | 匹配真实审批链（组长→经理→总监） | 中 |

| A4 | **EBOM/MBOM 多视图** | 单一 BOM | 设计与制造 BOM 分离，PDM→PLM 分水岭 | 高 |

## 五、建议的推进顺序

1. **A1 通知/消息中心** —— 投入产出比最高，用户日常最易感知，且能统一服务 ECR/ECO/项目/签出多个模块。
2. **A2 多级顺序审批** —— 字段已预留，改造集中在审批推进逻辑，风险可控。
3. **A3 BOM 高级概念** —— 分步交付（先 UOM + 行备注，再替代料/可选件）。
4. **A4 EBOM/MBOM** —— 作为迈向 PLM 的里程碑，需独立立项设计。

> 每一项进入实施前，应各自走独立的 brainstorming → spec → plan → implementation 周期。
