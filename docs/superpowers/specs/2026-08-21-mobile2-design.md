# 移动端 Web 适配设计（mobile2）

日期：2026-08-21
分支：feat/mobile2
状态：设计定稿，待实施

## 1. 背景与目标

现有前端为桌面优先的 React SPA（React 18 + Vite + TypeScript + Tailwind + react-router + zustand）。
上一轮移动端适配（feat/mobile 分支，2026-07-25）采用"桌面优先叠加响应式"路线，结果：
手机体验仍是桌面思路、覆盖不彻底。本设计**推倒重做**。

**目标**
- 移动端 = **纯只读查询**，无任何创建/编辑/审批操作。
- 桌面端**零改动**：移动端独立视图层，不修改现有桌面组件。
- 一套代码、同路由切换，URL 不变，不新建工程/子域名/独立 `/m/` 路由。

**使用场景**
- 生产现场查询：查零件/BOM/图纸（读操作为主）。
- 管理看板：看项目进度、库存概览、通知。

**首期范围**
- 覆盖模块（只读）：零部件管理（查询）、图文档管理（查询+预览）、用户看板（/board）、
  仪表盘（/dashboard）、通知中心、项目管理（进度查看）、库存管理（查询）、构型管理（查询）、
  变更管理（查看 ECR/ECO）。
- 预览：PDF / 图片 / Office（转 PDF）/ STP 3D 全支持；其余格式"请用电脑打开"占位。

## 2. 断点约定

- 以 Tailwind 默认 `md`（768px）为界：`< 768px` 判定为移动端，`≥ 768px` 保持现有桌面布局。
- 移动端目标设备**仅手机**；平板（≥768px）走桌面布局，不做专门适配。
- `viewport` meta 已存在于 `index.html`，无需改动。
- 新增 hook `useIsMobile`（重写旧版）：`window.matchMedia('(max-width: 767px)')`，
  监听变化返回布尔；SSR/无 matchMedia 时返回 false；补单测。
  （旧版误用 1023px 断点，本设计统一为 767px。）

## 3. 总体架构：独立移动视图层 + 同路由切换

```
frontend/src/
├── mobile/                    # 移动端视图层（新增目录，桌面代码零改动）
│   ├── MobileRoot.tsx         # 同路由切换入口：useIsMobile 为 true 时接管渲染
│   ├── MobileLayout.tsx       # 移动外壳：顶部 AppBar + 底部 Tab + 内容区
│   ├── MobileLogin.tsx        # 移动端登录页（复用 authApi / authStore）
│   ├── components/            # 移动通用件：MobileList / MobileDetail / 状态徽标 / 占位卡 / 抽屉
│   ├── pages/                 # 每模块一页：Parts / Documents / Board / Dashboard /
│   │                          #   Notifications / Projects / Inventory / Configuration / EC
│   └── nav.ts                 # 底部 Tab 配置 + 模块路由表（复用 can(perm) 过滤）
├── hooks/useIsMobile.ts       # 重写旧版（767px + 测试）
└── App.tsx                    # 唯一改动点：路由层加移动分支（约 10 行）
```

- **同路由切换**：`App.tsx` 现有 `<Layout>` 外套一层——`useIsMobile()` 为 true 时渲染
  `<MobileRoot>`（内部移动路由树，路径与桌面完全一致），false 时渲染现有桌面 `<Layout>`。
- URL 不变：通知跳转、刷新、分享链接天然可用；桌面代码文件一行不改。

## 4. 移动外壳

### 4.1 顶部 AppBar
- 当前页标题（复用 `usePageHeader` 或路由映射）+ 右侧 `NotificationBell`（已可独立工作）。
- 桌面版侧边栏顶部区块（用户信息/同步/登出）在移动端移入"更多"页。

### 4.2 底部 Tab（5 槽位）
1. **看板**（/board 用户看板）
2. **零部件**（/parts）
3. **图文档**（/documents）
4. **项目**（/projects）
5. **更多**（仪表盘 / 变更 / 库存 / 构型 / 通知 / 设置 / 退出）

- Tab 可见性走 `can(perm)` 角色过滤，与桌面侧边栏一致。
- Tab 切换以 URL 驱动（查询参数 `?tab=` 或子路由），保证手势返回可回退 Tab。

### 4.3 登录
- `/login` 在手机上渲染 `MobileLogin`：账号密码登录 + 飞书/微信登录按钮（复用现有 OAuth 跳转）。
- 登录成功回跳原目标页；未登录访问任何页面重定向到 `/login`。

## 5. 列表与详情交互模式

### 5.1 列表页（统一范式）
- 顶部**固定搜索框**：按编号/名称关键字实时搜索（复用现有 API 的 `keyword` 参数，服务端过滤）。
- 搜索框右侧**按需工具按钮**（如筛选展开、刷新）。
- 结果**卡片列表**：主标题 = 编号 + 名称；2–3 行关键字段（版本/状态/更新时间）；状态徽标彩色区分（复用桌面状态映射）。
- 类型/状态筛选：折叠为顶部横向 chip 行（如零部件：全部/零件/部件）。
- 下拉刷新（`touch` 事件实现，零依赖）。

### 5.2 详情页（全屏路由页，非弹窗）
- 每个模块独立详情路由（`/parts/:id`、`/documents/:id` 等），URL 与桌面同构。
- 顶部 AppBar：返回 + 标题。
- 主体**分段 Tab** 分区，每区独立卡片：
  - 零部件 = 概览 / BOM / 附件 / 版本 / Where-Used
  - 图文档 = 概览 / 附件预览 / 版本
  - 变更 = 详情 / 变更影响
- **BOM 树逐级下钻**：点子项进入下一层（`/parts/:id/bom/:childId`，面包屑返回），不渲染平铺大树。

### 5.3 搜索与跳转
- 通知点击 → 详情（同 URL 天然直达）。
- Where-Used 结果可点击跳转目标详情。

## 6. 附件预览

### 6.1 PDF / 图片 / Office（复用现有后端链路）
- PDF：`window.open('/api/v2/attachments/{id}/preview?token=…')` **新标签**打开，浏览器原生渲染。
- 图片：`<img>` 直接加载 stream/preview 接口。
- Office：走现有 LibreOffice 转 PDF 链路，转好后原生 PDF 渲染。
- 附件列表入口：卡片（文件名/大小/类型图标）→ 点击全屏预览；非支持格式显示"请用电脑打开"占位。

### 6.2 STP 3D（移动端重点）
- 独立全屏路由（`/stp-viewer`，复用现有路由，移动端渲染移动版查看器）。
- 触控：Canvas 容器 `touch-action: none`，ArcballControls 单指旋转 / 双指平移缩放。
- **模型树：左侧抽屉**（左缘滑出），选中高亮/定位。
- **工具：右侧抽屉**（右缘滑出，测量/剖切/爆炸/重置聚合，点区 ≥ 40px）。
- 顶部固定：返回按钮 + 模型名（返回按钮为兜底，手势返回为主）。
- 性能：`dpr` 上限 [1, 2]，沿用现有三档 LOD 流式加载。

## 7. 返回策略（与全面屏手势兼容）

- 移动浏览器全面屏返回手势 = 浏览器返回（`history.back()`，触发 `popstate`）；Android/iOS 一致，
  差异仅在动画表现（Android 13+ 预测性返回预览、iOS 左缘滑动跟随手指）。
- **popstate 是唯一权威的返回信号**：应用内返回按钮也调用 `navigate(-1)`（= history.back()），
  与手势完全同一机制，不存在两套逻辑。
- **不试图阻止系统返回**（网页无法阻止），而是让返回总是"关闭最上层 UI"（层级式）：
  1. 最上层是抽屉（模型树/工具/筛选）→ 手势返回 = 关闭抽屉（`pushState` 哨兵 + `popstate` 拦截）。
  2. 再返回 = 路由后退（详情 → 列表 → Tab 首页）。
  3. 每层都是真实 history 条目，手势返回永远有"东西"可退，不会误退出应用。
- 内部跳转一律用 SPA 路由（同文档导航，popstate 不重载页面）；仅 PDF 预览用 `window.open`
  开新标签（独立历史，与主应用互不干扰）。
- 回到最底层 Tab 后再次手势返回 = 退出浏览器/关闭标签，为平台默认行为，接受不做拦截。

## 8. 只读保证与权限

- **只读是结构性的**：移动视图层只渲染读交互——列表/搜索/详情/预览只用 `GET` 类 API；
  移动端组件树中不存在表单、提交、状态流转入口。
- 导航与数据仍按角色权限：Tab 可见性、模块访问继续用现有 `can(perm)` 过滤；
  管理员在手机上也只见只读视图（与桌面权限矩阵一致）。
- 会话复用现有 `authStore`（persist）。

## 9. 实施顺序（增量，每步可独立交付）

1. **地基**：重写 `useIsMobile`（767px + 测试）、`MobileRoot` 同路由切换、
   `MobileLayout`（AppBar + 底部 Tab + 更多页）、`MobileLogin`。
2. **核心查询**：零部件（列表/搜索/详情/BOM 下钻/Where-Used）、
   图文档（列表/详情/PDF·图片·Office 预览）。
3. **STP 3D**：移动查看器（触控 / 左侧模型树抽屉 / 右侧工具抽屉 / 返回）。
4. **铺开**：看板、仪表盘、项目进度、库存、构型、变更查看、通知中心。
5. **收尾**：非支持格式占位、返回拦截模式统一收口、真机回归。

## 10. 验证

- Chrome DevTools 375px / 390px 仿真 + 真机抽测（含 STP 触控手势、全面屏返回逐层行为）。
- 桌面 ≥768px 逐页回归（桌面代码零改动，回归面极小）。
- `npm run build` 通过；`useIsMobile` / 移动组件单测 `npm run test` 绿。

## 11. 明确不做（YAGNI）

- 不新建工程 / 子域名 / 独立 `/m/` 路由。
- 不做任何移动端编辑/创建/审批功能（纯只读）。
- 不引入新的 UI 组件库；沿用现有 Tailwind + primary 配色。
- 不做 PWA / 离线缓存。
- 不做平板适配（≥768px 用桌面布局）。
- 不重写桌面端任何组件。
